能力五层 × 标准六块

原文的五层是"技术栈分层"，ISO 13374 的六块是"信息处理职能"。两者正交映射，才能做到每一层有标准可依、每一个输出有责任主体。

协议无关

上层只认 site.area.asset.component.point.quantity 六段路径，换 PLC 不影响任何上层逻辑。

证据可回放

给定 trace_id，能重建当时的数据快照、特征、规则、模型版本、确认人与签字时间。

降级优于崩溃

断网、掉线、模型不可用时，按四级降级链继续输出，最差也给出"仅告警不带建议"。

02

四层方法论，互不替代

治理层管"该不该做"，标准层管"做得对不对"，工程层管"怎么保证"，运行层管"跑得稳不稳"。

治理 TOGAF 10 ADM

A 架构愿景 → B 业务 → C 数据/应用 → D 技术 → E/F 迁移规划 → G 治理。项目级裁剪，不做全周期。

标准 国标 + 国际标准

GB/T 8567 文档、GB/T 22239 等保三级、GB/T 45654 生成式 AI、GB/T 45288.1 大模型、ISO 13374 / ISO 20816 / IEC 62443 / ISO 42001。

工程 SDD · TDD · BDD · ATDD

规格是唯一真相源；每条需求至少一条 Gherkin；核心算法先写测试；三方评审产出验收标准。

运行 Agent Harness 工程

Agent = Model + Harness。10 组件落地：循环 / 工具 / 沙箱 / 权限 / 记忆 / Hooks / 子智能体 / 技能 / 观测 / 评测。

⚠️ 两个 Harness，别混用

Harness（工程范式）：把大模型变成可靠智能体的整套外围基础设施，本文档集的核心。
Harness.io（商业平台）：CI/CD 与软件交付平台，用于流水线与质量门禁。
二者在本项目都会用，但属于完全不同的层。混用会让设计评审直接跑偏。

G1 是最容易被糊弄的门

很多项目在这里妥协（"先跑起来再说"），然后在 Ph2 花三倍时间还债。数据不达标，不进 Ph2。

M4 是信心拐点

第 9 周必须有一次真实、可验证的提前预警。没有就停下复盘，不要硬推 Ph3。

退出策略写进计划

G1 三次不过 → 暂停做数据治理专项；召回率 < 60% 无改善路径 → 缩范围为规则告警。

风险 LimiX-2 权重非商用

原文推荐 LimiX 为"第 2 层核心"。核实后：代码 Apache 2.0，但 LimiX-2 权重遵循非商用许可。

  • POC：可用
  • 生产：禁用，除非取得书面商用授权
  • 基线：经典特征 + 树模型（无许可风险、可解释）

修正 原文未覆盖的三件事

  • 裸 MCP 缺权限/审计/护栏 → 必须加 Harness 运行时
  • 四角色会诊会互相附和 → 必须加独立 Evaluator
  • AG 建议要分两级：给人看（解释）与给系统看（执行）
