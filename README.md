## 0. 一句话定位

不是再做一个"更准的故障预测模型"，而是把 **ISO 13374 的六功能块**（DA→DM→SD→HA→PA→AG）用 **Agent Harness 工程**贯通，交付一个**可审计、可降级、可回滚、带排产与备件约束的维护决策系统**。

原文的判断我们完全接受并写进方案首页：

> **预测性维护的终点不是"预测得更准"，是"决策得更优"。**

但原文停在"装配顺序"，本方案要把它变成**可招标、可验收、可审计**的工程基线。

### 3.6 集群实盘结论（docs/16）

`10.167.2.175` = k8s-master（16C/126Gi），`10.167.2.176` = k8s-worker1（64C/126Gi），K8s v1.28.2，Rancher + Fleet + Istio 已装，docker 26.1.4，实际 CPU 用量仅 2–10%。

**已有可复用**：Pulsar、TiDB+TiFlash、Milvus、NebulaGraph、CockroachDB、Redis、Nacos、LiteLLM、Ollama、Prometheus/Grafana/Loki、NFS provisioner。
**必须新建**：TDengine（时序）、本项目服务。关系库按 D23 复用 TiDB（见 docs/17 §8），不再新建 PG。
**两个风险**：该集群承载教学/实验业务，须强隔离；master 根分区仅余 15G，波形不能放。

### 3.7 TiKV OOM 已修复（docs/18）

不是单一 OOM，而是五因一链：节点内存超卖（limit 总和 157%–203%）→ load-testing 无配额 → kubelet 驱逐 Burstable Pod → PD 先崩 → TiKV 退出时腾 leader 超时 → SIGKILL(137)。

已执行 9 项修复：TiKV request 1Gi→2Gi、grace 30s→300s、PD limit 512Mi→2Gi、TiFlash 从"无限制"→16Gi、load-testing 加配额、新增 `pdm-data-critical` 优先级类、TiFlash 改 Recreate 策略。**验证：8 个 Pod 全部 Running，TiDB v8.5.8 健康。**
