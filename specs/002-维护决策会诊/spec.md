## 1. 为什么这是核心（Why）

原文的核心判断：

> 卡点从来不在"预测"，在预测之后那一步。
> 一次非计划停机的平均损失，往往是同规模计划停机检修的五到十倍。

**本 spec 交付的就是"那一步"。** 它不是"给个建议"，而是给出一张**带排期、备件、人力、成本、风险的方案卡**。

一句话验收标准：**维修主管拿到这张卡，不需要再问任何人就能安排工作。**

## 3. 功能需求（EARS）

### 3.1 会诊

| ID | 需求 |
|---|---|
| FR-002-01 | [Event] 当触发会诊（橙色及以上 / 人工发起）时，系统应并行召集 4 个角色，各自在 30 秒内输出结构化意见。 |
| FR-002-02 | [Ubiquitous] 每个角色只能访问其授权数据域（车间经理不看成本、生产经理不看 RUL 细节）。 |
| FR-002-03 | [Ubiquitous] 系统应设置独立评估者，对 4 份意见做一致性与证据充分性校验，且不得由生成方自评。 |
| FR-002-04 | [State] 当一致性评分 < 0.6 时，系统应标注"存在分歧"并列出冲突点，交人工裁决。 |
| FR-002-05 | [Event] 当证据不足时，系统应回退补充证据（最多 2 轮），仍不足则输出"证据不足，建议人工评估"。 |

### 3.2 方案卡

| ID | 需求 |
|---|---|
| FR-002-06 | [Ubiquitous] 方案卡必须包含：结论、置信度、证据、≥1 个窗口方案、备件清单、人力需求、成本分解、风险、待确认项。 |
| FR-002-07 | [Ubiquitous] 每个窗口方案必须计算：停机成本、备件成本、人工成本、延期风险成本、净收益。 |
| FR-002-08 | [Unwanted] 若推荐窗口早于关键备件到货日，系统不得推荐该窗口。 |
| FR-002-09 | [Event] 当存在排产冲突时，系统应给出 ≥ 2 个备选窗口并对比代价。 |
| FR-002-10 | [Ubiquitous] 方案卡必须标注"AI 辅助生成"，且不构成维修指令。 |

### 3.3 确认与闭环

| ID | 需求 |
|---|---|
| FR-002-11 | [State] 方案卡在人工确认前，状态为 `PENDING`，不可转为工单。 |
| FR-002-12 | [Event] 当人工确认时，系统应签发一次性确认令牌（有效期 2 小时，绑定卡号与确认人）。 |
| FR-002-13 | [Event] 当确认后创建工单时，系统应回写工单号；无回执不得标记完成。 |
| FR-002-14 | [Unwanted] 若 EAM 调用失败，系统应重试 3 次后转人工队列，并标记"未闭环"。 |
| FR-002-15 | [Event] 当方案卡被拒绝时，系统应要求选择原因码（误报/时机/成本/其他+说明）。 |

### 3.4 告警联动

| ID | 需求 |
|---|---|
| FR-002-16 | [Event] 当橙色告警 72 小时未确认时，系统应升级至设备科长。 |
| FR-002-17 | [Event] 当红色告警 4 小时未确认时，系统应升级至设备副总并短信通知。 |

## 5. 验收标准

### AC-1 四角色会诊
- [ ] 触发会诊后 60 秒内产出 4 份结构化意见
- [ ] 每份意见含：结论、依据、约束、风险

### AC-2 独立评估
- [ ] 评估者输出一致性评分、冲突列表、证据充分性
- [ ] 构造冲突场景（生产建议 10/28，维修指出备件 10/30 到）→ 评分 < 0.6 且冲突被列出

### AC-3 备件约束（关键）
- [ ] 备件 10/30 到货 → 推荐窗口起始 ≥ 10/30
- [ ] 若唯一可用窗口早于到货日 → 输出"建议等待备件"或"建议调拨"，**不得推荐该窗口**

### AC-4 经济性
- [ ] 每个窗口含 4 项成本 + 净收益
- [ ] 净收益 = 避免损失 − 总成本，计算可复核

### AC-5 多窗口
- [ ] 有排产冲突时 ≥ 2 个备选窗口，含代价对比表

### AC-6 写操作安全
- [ ] 无确认令牌调用建单 → 拒绝（PDM-3002）
- [ ] 令牌过期 → 拒绝
- [ ] 令牌与卡号不匹配 → 拒绝

### AC-7 回执校验
- [ ] EAM 超时但 Agent 声称成功 → Stop Hook 拦截，转人工

### AC-8 拒绝归因
- [ ] 拒绝必须选原因码，否则不可提交

## 6. 方案卡字段规范（强制）

| 区块 | 字段 | 必填 |
|---|---|---|
| 标识 | card_id, asset_id, created_at, diag_id | ✅ |
| 诊断 | conclusion, confidence, evidence[] | ✅ |
| 预后 | rul_p10/p50/p90, assumptions[] | ✅ |
| 方案 | options[]（≥1） | ✅ |
| 单方案 | window, downtime_h, production_impact, spare_ready, crew, cost{}, risk | ✅ |
| 经济性 | avoided_loss, total_cost, net_benefit | ✅ |
| 冲突 | conflicts[] | 可为空 |
| 确认 | required_roles[], deadline, status | ✅ |
| 免责 | disclaimer | ✅ |

**缺任一必填字段 → 卡片不可提交（服务端校验，非前端校验）。**

---

## 7. 边界

- ❌ 不自动派工
- ❌ 不自动下采购单
- ❌ 不修改排产计划（只给建议）
- ❌ 不评估设备设计缺陷

## 8. 开放问题

| # | 问题 | 建议 |
|---|---|---|
| Q1 | 会诊是否每次都跑 4 角色（成本 ×4） | 橙色以上跑全量；黄色只跑维修+可靠性 |
| Q2 | 经济性口径由谁定 | 财务出模板，项目组实现 |
| Q3 | 拒绝原因码是否可扩展 | 固定 4 类 + "其他"说明，季度评审扩充 |
| Q4 | 多设备同时告警时是否合并会诊 | 同部件合并；不同设备独立 |
