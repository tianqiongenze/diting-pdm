| 项 | 内容 |
|---|---|
| Spec ID | SPEC-003 |
| 关联需求 | FR-701 ~ FR-704、NFR-08、NFR-09 |
| 优先级 | P0（一票否决项） |
| 状态 | Draft |
| 依赖 | SPEC-001（本地诊断能力） |

---

## 1. 为什么单独成 spec（Why）

原文第七节的核心结论：

> 对很多工厂来说，"在哪儿跑"是个一票否决项——数据能不能出厂区，往往不由技术团队决定。

以及验收清单里那条：

> 断网、传感器掉线时系统能降级运行，不会整体崩溃。

**"降级"不是一个功能，是一组必须在架构期就设计好的行为。** 它最容易在演示时被忽略（因为演示时网络总是好的），也最容易在第一次断网时暴露。

单独成 spec，是为了让它在测试计划里有独立的位置，而不是散落在各处的"异常处理"。

---

## 2. 核心设计原则

| 原则 | 含义 |
|---|---|
| **边缘自治** | 中心不可达时，边缘必须能独立完成"采集→诊断→告警" |
| **显式降级** | 任何降级必须标记，不得静默 |
| **优先级淘汰** | 存储不足时，按价值淘汰（结论 > 特征 > 波形） |
| **补传幂等** | 恢复后补传不得产生重复告警/重复工单 |
| **版本可控** | 边缘更新必须可回滚，保留上一版本 |

## 3. 功能需求（EARS）

### 3.1 断网自治

| ID | 需求 |
|---|---|
| FR-003-01 | [Unwanted] 若边缘与中心失联，边缘应在 10 秒内检测到并切换至自治模式。 |
| FR-003-02 | [State] 自治模式下，边缘应继续执行：采集、特征计算、SD/HA、本地告警。 |
| FR-003-03 | [State] 自治模式下，边缘应缓存待上传数据（特征值 + 事件 + 结论），缓存 ≥ 72 小时。 |
| FR-003-04 | [Unwanted] 若自治模式下需要 LLM 而本地模型不可用，应降级为模板化报告 + 规则结论。 |
| FR-003-05 | [Event] 当网络恢复时，边缘应在 5 分钟内完成补传，且补传数据带原始时间戳。 |

### 3.2 传感器降级

| ID | 需求 |
|---|---|
| FR-003-06 | [Unwanted] 若某测点连续 5 分钟无数据，应标记 `STALE`，且不影响其他测点。 |
| FR-003-07 | [Unwanted] 若关键测点（振动）失效，应降级使用辅助测点（温度/电流），并下调置信度 ≥ 30%。 |
| FR-003-08 | [Unwanted] 若全部振动通道失效，系统应输出"无法评估"，**不得输出"正常"**。 |

### 3.3 存储管理

| ID | 需求 |
|---|---|
| FR-003-09 | [Event] 当边缘存储使用率 > 85% 时，应按优先级淘汰：原始波形 → 原始报文 → 特征值（保留最近 90 天）。 |
| FR-003-10 | [Ubiquitous] 结论、告警、审计记录**永不淘汰**（除非人工清理）。 |

### 3.4 更新与授权

| ID | 需求 |
|---|---|
| FR-003-11 | [State] 边缘应在每日 02:00–04:00 窗口拉取更新，不得主动推送。 |
| FR-003-12 | [Unwanted] 若更新包签名校验失败，应拒绝安装并告警。 |
| FR-003-13 | [State] 边缘应保留上一版本，支持 15 分钟内回滚。 |
| FR-003-14 | [Event] 当离线授权剩余 < 30 天时，应告警；到期后进入"只读监测"模式（不停机）。 |

### 3.5 时间与一致性

| ID | 需求 |
|---|---|
| FR-003-15 | [Unwanted] 若边缘时钟偏差 > 50 ms，应告警并在补传时标注"时间可能不准"。 |
| FR-003-16 | [Unwanted] 若断网期间发生时钟跳变，应保留原始时间戳 + 记录跳变事件，不得静默修正。 |

## 4. 验收标准

### AC-1 断网 30 分钟
- [ ] 10 秒内检测到失联
- [ ] 本地诊断持续可用
- [ ] 本地告警正常推送（企业微信/短信走本地出口或缓存）
- [ ] 恢复后 5 分钟内补传完成
- [ ] 补传数据时间戳为原始时间

### AC-2 断网 72 小时
- [ ] 缓存不溢出（按 20 台设备估算 < 20 GB）
- [ ] 无数据丢失（特征值 + 结论）
- [ ] 恢复后补传完整，无重复告警

### AC-3 LLM 不可用
- [ ] 停掉本地模型服务 → 仍输出模板报告
- [ ] 报告含：结论、证据、建议动作
- [ ] 报告标记 `degraded=true` 与"AI 能力受限"

### AC-4 通道失效
- [ ] 拔掉 2/4 振动通道 → 标记降级，置信度下调
- [ ] 拔掉全部振动通道 → 输出"无法评估振动"，不输出"正常"

### AC-5 存储压力
- [ ] 填满磁盘至 90% → 按优先级淘汰
- [ ] 结论/告警/审计 0 丢失

### AC-6 更新回滚
- [ ] 安装坏版本 → 自动回滚（< 15 分钟）
- [ ] 回滚后服务正常

### AC-7 授权到期
- [ ] 到期后不停机，进入只读监测
- [ ] 提前 30 天告警

## 5. 部署要求

| 项 | 要求 |
|---|---|
| 边缘 OS | Ubuntu 22.04 / 麒麟 V10 |
| 编排 | K3s（单节点或 3 节点） |
| 资源 | 8C / 32G / 512G SSD（20 台设备） |
| 可选 GPU | ≥ 8 GB（本地小模型） |
| 网络 | 工业环网，支持断连 |
| 电源 | UPS ≥ 30 分钟 |
| 防护 | 工业级机箱，-10~50℃ |

---

## 6. 边界

- ❌ 不在边缘做模型训练
- ❌ 不在边缘存超过 90 天波形
- ❌ 不支持边缘间横向通信（避免形成影子网络）
