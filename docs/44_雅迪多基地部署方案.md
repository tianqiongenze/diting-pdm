### 三种部署模式

| 模式 | 适用 | 资源 | 数据策略 |
|---|---|---|---|
| **完整边缘** | 大型基地（>500 台） | K3s + TiDB + Rust 采集 | 本地全量数据，上行摘要 |
| **轻量边缘** | 中型基地（100-500 台） | K3s + 外部 TiDB | 本地诊断，数据上行 |

## 三、边缘集群部署（K3s）

### 3.1 边缘 K3s 清单（本轮已实现）

见 `impl/deploy/k8s/edge/edge-site.yaml`。核心要点：

- **K3s**：单节点或双节点，资源占用低（<2C4G）
- **TiDB 本地**：仅 TiKV（读副本），或用 SQLite（小基地）
- **Rust 采集器**：接 PLC/传感器，本地 DSP
- **本地诊断**：python-diagnosis 边缘副本，断网可独立闭环
- **本地看板**：ConfigMap 挂载，`?tenant=site-xxx` 区分基地

### 3.2 边缘自治铁律

1. **判据只在集团，数据只在基地**。边缘定期拉取集团判据（`/v1/rules?scope=group`），断网时用本地缓存
2. **上行是"受控摘要"**。仅特征值/事件/诊断结论/方案卡上行，原始波形不出基地
3. **边缘永远能独立闭环**。采集→诊断→告警→本地报告全链路，断网不中断

### 3.3 边缘部署脚本

见 `impl/tools/deploy-site.sh`（本轮已实现）：

```bash
# 用法：部署一个新基地
bash tools/deploy-site.sh --site site-b --nodes 192.168.20.10 --devices 500

# 脚本自动：
# 1. 在边缘节点安装 K3s
# 2. 部署 TiDB 本地副本（或 SQLite）
# 3. 部署 python-diagnosis 边缘副本
# 4. 部署 Rust 采集器
# 5. 配置集团判据拉取 CronJob
# 6. 验证本地闭环
```

## 四、多租户与数据隔离

### 4.1 租户模型

| 租户 ID | 类型 | 设备数 | 数据位置 |
|---|---|---|---|
| `site-a` ~ `site-t` | 基地 | 300-800 | 本地 + 集团汇总 |
| `supplier-xxx` | 供应商 | <50 | 仅本地，上行质量数据 |
| `group` | 集团 | — | 聚合视图（无单台数据） |

### 4.2 隔离四层（缺一不可）

| 层 | 机制 | 实现 |
|---|---|---|
| 身份 | HMAC token（含 tenant） | `auth.py` issue_token |
| 网关 | NetworkPolicy + Ingress | 每基地独立 Ingress host |
| 数据 | TenantQueryBuilder + 逐行断言 | `repository.py:49-73` |
| 消息 | Pulsar namespace | `tenant/site-a/*` |

### 4.3 多租户 CronJob（本轮已实现）

3 个 CronJob 全部改为 `$TENANTS` 环境变量循环：

```yaml
env:
- name: TENANTS
  value: "site-a,site-b,site-c"   # 逗号分隔，一个 CronJob 管全部基地
```

## 五、判据统一发布与版本化

### 5.1 发布流程

```
集团设备主管在管理台调整阈值
    ↓
POST /v1/rules/group/publish {rule_id, threshold, ...}
    ↓
alert_rule 表写入新行（version = max+1，scope=group）
    ↓
各基地 CronJob（每 10 分钟 alert-sync）拉取集团判据
    ↓
基地 24h 内全部生效（FR-904）
```

### 5.2 版本回滚

```bash
# 查看历史版本
curl -H "X-Tenant-Id: site-a" .../v1/rules?scope=group&version=1

# 回滚到指定版本（发布旧版本号即回滚）
curl -X POST .../v1/rules/group/publish -d '{"rule_id":"HI_WARNING","threshold":70,"version":1}'
```

## 六、数据主权与跨境合规

### 6.1 数据分级

| 级别 | 定义 | 境内 | 海外 |
|---|---|---|---|
| L1 原始波形 | 含工艺细节 | 留基地 | **强制留基地** |
| L2 设备台账 | 敏感 | 可上行 | 留基地，汇总上行 |
| L3 诊断结论 | 内部 | 可上行 | 脱敏后上行 |
| L4 统计指标 | 可共享 | 可上行 | 可上行 |

### 6.2 海外合规

- 本地处理、最短留存、可删除、可导出
- 通过"本地自治 + 脱敏上行"满足 GDPR/越南 PDPD
- 海外基地缓存 168h（7 天），弱网更久

### SQLite 替代 TiDB 的边缘决策（ADR）

**结论：边缘用 SQLite，集团用 TiDB。** 依据：

| 维度 | TiDB | SQLite（边缘） |
|---|---|---|
| 资源 | 每副本 ≥2C4G | <100MB 内存 |
| 运维 | PD/TiKV/TiDB 三组件 | 单文件 + WAL |
| 并发写 | 分布式强一致 | 单写者（边缘采集够用） |
| 数据规模 | 亿级 | 十万级（按窗口清理） |

实现要点（repository.py）：
- `PDM_DB_BACKEND=sqlite` 切换，仓库函数零改动
- 方言转换覆盖：`%s→?`、`INSERT IGNORE→INSERT OR IGNORE`、
  `ON DUPLICATE KEY UPDATE→ON CONFLICT DO UPDATE`（_UPSERT_PK 登记 5 表）、
  `NOW()→datetime('now')`、`TIMESTAMPADD(HOUR,...)→datetime(col,'+n hours')`
- `isolation_level=None` 真 autocommit——否则连接关闭时未提交写入被静默回滚（冒烟测试验证）
- DATETIME 注册转换器，读回仍是 datetime 对象（上层 isinstance 判断依赖）
