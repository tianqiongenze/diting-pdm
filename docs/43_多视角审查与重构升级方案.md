## 四、AI 教授级高工视角（算法与模型）— 5.0/10

### 优势
| 项 | 证据 |
|---|---|
| HI 计算完全可解释 | domain.py 规则驱动，每个维度有 evidence 字段 |
| RUL 有边界保护 | repository.py:estimate_rul，历史不足 3 点返回 NULL，斜率≤0 返回 NULL |
| 降级结果不缓存 | server.py:809 `cacheable=lambda r: not r["degraded"]` |
| 批量诊断共享核心 | `_run_single_diagnose` 单点与批量共用，避免行为漂移 |

### 差距
| 问题 | 证据 | 影响 |
|---|---|---|
| **模型版本是字符串常量** | domain.py `MODEL_VERSION = "0.1.0"`，无版本表 | 无法做 A/B 对比、无模型迭代记录 |
| **无模型训练管线** | 无训练脚本、无特征存储、无评测集 | 算法迭代只能靠改代码 |
| **RUL 只有线性外推** | 无指数/卡尔曼滤波等替代方案 | 非平稳劣化场景不准 |
| **无反馈闭环** | 预测了故障、做了保养，但没记录"预测 vs 实际" | 无法量化模型准确率 |
| **知识库手动录入** | knowledge_case 靠人工填 | 诊断结论无法自动沉淀 |
| **无漂移检测** | 无数据分布监控 | 工况变化后 HI 可能系统性偏移 |
| **LLM 集成未实现** | docs/14 提到 LiteLLM+Milvus，代码中无 | AI 会诊功能缺失 |

### 风险
- **中风险**：模型不可迭代是长期隐患——工厂工况变化后 HI 会漂移，但无检测机制
- **建议**：至少加一个 `model_version` 表 + 诊断结果自动写入知识库的钩子

## 九、关键教训（本轮审查发现）

1. **"设计完备"不等于"可交付"**：docs/14 画了完美的联邦架构，但代码只有 1 个租户——评审时被问"第 2 个基地怎么接"会卡住
2. **CronJob 硬编码是隐性技术债**：配置写死在 YAML 里，每接一个基地改 3 处，违反配置与代码分离
3. **判据无版本化 = 集团对标不可信**：FR-903 要求"同型号同判据"，但当前 `alert_rule` 无版本号，改了阈值不知道哪些基地还在用旧版
4. **AI 模型无版本 = 无法迭代**：`MODEL_VERSION` 是字符串常量，改了代码就丢了历史，无法对比新旧模型效果

> 以上教训已同步写入 docs/44（部署方案）与 docs/45（重构交付报告）。

## 十、先进技术落地差距分析（2025–2026 联网对标）

| 概念 | 文档承诺（位置） | 代码现实（实测） | 落地度 | 差距性质 |

"设计定位（实现状态）"，逐行标注 ✅已实现 / 🔨设计中 / ❌未启动，与代码现状对齐。

### 10.3 为什么世界模型对 PdM 是刚需（不是追热点）

2025–2026 业界进展（ICCV 2025 高斯世界模型 GWM、制造业 AI 落地调研）指向同一结论：
PdM 的瓶颈不在"预测更准"，而在**决策推演**——"如果推迟 2 周保养，HI 会掉到多少？
这期间非计划停机概率多大？"当前实现只有线性外推 RUL（`repository.estimate_rul`），
**无法回答反事实问题**，方案卡的经济性数字因此缺乏依据。

落地形态（分两级，与工业安全红线兼容）：
- **L1 统计世界模型**（本期）：基于 `read_asset_health_history` 学习 HI 退化动态
  （线性 + 集成/高斯过程），输出**带不确定性区间**的反事实推演。可解释、无 LLM 依赖、
  输出必须带置信区间（不编数字，与 RUL 三边界同一纪律）。
- **L2 神经世界模型**（预留）：学习型退化仿真 + 情景生成，接口与 L1 一致可替换。

### 10.4 MCP/A2A 的互补关系（架构定位）

2025-04 Google 发布 A2A 并捐赠 Linux Foundation，2025-12 MCP 移交 AAIF 基金会，
2026-08 A2A 加入 AAIF 与 MCP 同治理框架。业界共识：
- **MCP 管"智能体连工具"**（本项目的 5 工具 + 设备/判据资源）
- **A2A 管"智能体连智能体"**（集团专家 Agent ↔ 基地 Agent ↔ 供应商 Agent 的任务协作）

对本项目的直接价值：
- A2A Agent Card → 供应商域受控接入（FR-907：供应商上报质量异常 → 关联来料批次 → 通知 SQE）
- A2A tasks/send → 跨基地专家代诊（集团可靠性工程师远程会诊小基地设备）
- MCP Resources → 判据库/故障模式库的只读标准化暴露（比当前"只有工具"更完整）

### 10.5 MCP 安全警示（2025 实证）

2025 年 MCP 生态曝出多类漏洞（工具投毒、令牌泄露、SSRF）。工业场景必须：
工具来源白名单 + 每次调用审计（已有 audit_log 基础）+ 边缘侧禁 sampling（防数据外泄）。
