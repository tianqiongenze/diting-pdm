### 1.5 十条关键判断

| # | 判断 | 依据 |
|---|---|---|
| J1 | 事件总线用 **Pulsar，不新建 Kafka** | 已存在，且 tenant/namespace 多租户模型匹配 20 基地 |
| J2 | 读侧分析用 **TiDB + TiFlash，不上 ClickHouse** | 已存在，TiFlash 列式足以支撑对标聚合 |
| J3 | 向量库用 **Milvus**，图库用 **NebulaGraph** | 均已存在，少建 2 个组件 |
| J4 | 可观测**不自建**，OTel Collector 推送到现有 Prometheus / Loki | 已有完整栈 |
| J5 | LLM 链路用 **LiteLLM + Ollama（本地）** | 已存在，本地化满足数据不出厂 |
| J6 | 关系库**需新建专用 PG**（不复用 Dify 的） | 生产隔离；PG 主从天然支撑 CQRS |
| J7 | **时序库必须新建**（集群无 TDengine / InfluxDB） | 唯一必须新建的核心存储 |
| J8 | MQTT 用 **Pulsar 的 MQTT on Pulsar 适配器**，不引 EMQX | 复用已有，少一个组件 |
| J9 | **这是教学/实验平台集群**（openedx / jupyterhub / dataagent-course / ai-platform / dify） | 生产负载必须强隔离 |
| J10 | **磁盘是最大容量风险** | master `/` 仅余 15G，波形存储需另找承载 |

> **J9 是本次盘点最重要的结论。** 这个集群承载教学与实验业务，PdM 上生产必须做到四条：
> 1. 独立命名空间 `pdm-prod` + `ResourceQuota` + `LimitRange` + `NetworkPolicy` 默认拒绝
> 2. 数据密集组件（TDengine / PG）调度到 `k8s-worker1`，避免污染 master
> 3. 原始波形放 NFS 或外部存储，**绝不放 master `/`**
> 4. 与平台方书面确认资源预留，明确"这是生产负载，请勿误删"

## 2. 多语言职责矩阵

### 2.1 分工表

| 语言 | 承担域 | 具体职责 | 选它的理由 | 不选它的理由 |
|---|---|---|---|---|
| **Rust** | 监测域（边缘） | 协议解析（Modbus/OPC UA/S7/MQTT）、DSP 计算核（FFT/包络/希尔伯特）、波形编解码、边缘采集代理 | 无 GC、零成本抽象、内存可控、单线程 DSP 吞吐高、24×7 长稳 | 生态不如 Python，AI 算法难写 |
| **Go** | 运营域 + 基础设施 | Kafka/Pulsar 消费管线、GraphQL BFF 网关、告警路由、审计链、读模型投影器、OTel Collector | 高并发 I/O、二进制单文件、K8s 生态原生、部署极简 | 数值计算不如 Rust，生态不如 Java |
| **Java** | 资产域 + 知识域 + 应用集成 | 组织树与权限（复杂层级）、EAM/ERP/SAP 适配、规则引擎、判据库管理、多租户管理、BPM 审批流 | 企业中间件生态最全、连接器丰富、注册中心 Nacos 天然契合、运维体系成熟 | 启动慢、内存占用高、不适合高频 DSP |
| **Python** | 诊断/预后/决策/智能体 | 特征工程、HI/RUL 算法、模型服务、Agent Harness 运行时、MCP Server、会诊、报告渲染 | AI 生态唯一选择，无法替代 | 并发与长稳弱，不适合做网关与协议栈 |

### 2.2 边界规则（防止语言战争）

| 规则 | 说明 |
|---|---|
| **按部署边界划分，不按目录** | 每种语言是一个独立构建单元、独立镜像、独立发布线 |
| **跨语言一律走接口，不走 FFI** | 优先 gRPC / Pulsar，禁止 Rust cdylib 被 Python 直接调（调试地狱） |
| **DSP 核可作为独立 Rust 服务** | Python 通过 gRPC 调用 `dsp-service`，而不是引入 C 扩展 |
| **共享契约单独成仓** | `pdm-contracts` 仓维护 protobuf / JSON Schema / CloudEvents schema，多语言生成 |
| **统一门禁，不统一语言** | 单测覆盖率、SAST、SBOM、镜像签名对四种语言一视同仁 |

### 2.3 跨语言调用矩阵

```
Rust ──gRPC──▶ Go     （协议解析结果 → 事件管线）
Go   ──gRPC──▶ Java   （资产/权限查询）
Go   ──gRPC──▶ Python （读模型 → 智能体工具）
Rust ──gRPC──▶ Python （DSP 特征 → 诊断算法）
Java ──gRPC──▶ External EAM/ERP
Python ──grpc──▶ 全部（Agent 作为编排方）
```

**唯一例外**：Python 调 Rust DSP 时，若延迟敏感可编译为 `pdm-signal` 的 `cdylib` 通过 `pyo3` 暴露，**但仅限纯函数（无状态、无 IO）**，且必须有用例覆盖。

### 3.2 多语言流水线（统一门禁）

```
                ┌──────────────────────────────┐
   触发          │ Language Router（按变更路径）   │
                └───────────┬──────────────────┘
                            │
        ┌─────────┬─────────┼─────────┬─────────┐
        ▼         ▼         ▼         ▼         ▼
     Rust      Go        Java    Python   contracts
        │         │         │         │         │

                │ · 覆盖率统一阈值 80%（核心 90%） │
```

> **门禁必须统一。** 多语言项目最常见的失败是"Python 严、Rust 松"，三个月后质量分层、互相甩锅。

## 4. 基础设施适配设计

### 4.1 复用矩阵（决定 D14 / D15 的最终答案）

| 能力 | v1 计划的 | v2 实际（复用存量） | 变更原因 |
|---|---|---|---|
| 消息总线 | Kafka | **Pulsar（pulsar-broker.infra:6650）** | 已存在 + 多租户原生 |
| 时序库 | TDengine | **仍需新建 TDengine（集群无）** | 无替代 |
| 关系库 | PostgreSQL 16 | **新建专用 PG16（不复用 Dify 的）** | 需 RLS 做多租户硬隔离，见 docs/17 |
| 分析读模型 | 无 | **TiDB + TiFlash（复用）** | 已存在且够用 |
| 缓存 | Redis 7 | **Redis（redis.infra）** | 已存在 |
| 向量库 | pgvector | **Milvus（milvus.infra）** | 已存在，专业 |
| 图库 | Neo4j | **NebulaGraph（nebula-graphd.infra）** | 已存在 |
| 对象存储 | MinIO | **MinIO（milvus-minio.infra）** | 已存在，需确认配额 |
| 注册配置 | 自研 + Consul | **Nacos（nacos.infra）** | 已存在，Java 生态契合 |
| LLM 网关 | LiteLLM | **LiteLLM（litellm.ai-platform）** | 已存在（版本较旧需确认） |
| 本地推理 | vLLM 自建 | **Ollama（ollama-*.ai-platform）** | 已存在 |
| 可观测 | 自建 OTel 全家桶 | **OTel Collector + 现有 Prometheus / Grafana / Loki** | 已存在 |
| CI/CD | Harness.io | **Harness.io 或 Fleet GitOps（Fleet 已装，优先）** | Fleet 适配边缘管理 |
| 边缘管理 | 自研 | **Rancher Fleet（已装）** | 20 基地边缘管理天然适配 |

**净结果：需要新建的核心组件只剩 3 个**：TDengine、PG16、本项目自身服务。这显著降低了交付成本，也证明"先盘点再设计"是对的。

### 4.2 部署隔离设计（namespace: pdm-prod）

```
namespace: pdm-prod
├── ResourceQuota: cpu 20 核 / mem 60Gi / pods 80
├── LimitRange: 默认 requests/limits
├── NetworkPolicy: 默认拒绝，显式放行
│     ├── 允许 → infra（pulsar / tidb / milvus / nebula / redis / nacos）
│     ├── 允许 → ai-platform（litellm / ollama）
│     ├── 允许 → monitoring（prometheus remote-write / loki）
│     └── 允许 → ingress-nginx
├── 节点亲和：TDengine / PG 强制调度到 k8s-worker1
└── PriorityClass: pdm-prod-high（避免被批量任务抢占）
```

## 7. 智能体运行时的语言归属（2026-10-25 对齐）

| 能力 | 归属语言 | 理由 |
|---|---|---|
| 诊断规则引擎、世界模型、Harness、记忆、MCP/A2A | **Python**（python-diagnosis） | 科学计算生态（numpy/scipy）+ 快速迭代；Harness 与工具契约同源 |
| 资产台账与查询服务 | Java（java-asset） | 与集团主数据/EAM 生态一致 |
| 边缘高频采集 | Rust（pdm_signal / 采集器） | 低延迟、内存安全 |
| 事件管道 | Go（go-eventpipe） | 高并发转发 |

**新增约束**：Python 服务承载了 Harness 与协议层，其依赖清单必须纯净构建验证
（曾因缺 `pymysql` / `pulsar-client` 导致静默降级，见 docs/09 §11.3）。
