## 3. 本轮解决的"服务器无外网"问题（完整结论）

### 3.1 诊断过程（三层澄清）

| 测试 | 结果 | 结论 |
|---|---|---|
| `curl https://charts.pingcap.org` | HTTP 000，0.06s | 立即拒绝 |
| `ping mirrors.aliyun.com` | **26ms，0 丢包** | 网络层通 |
| `curl -4 https://mirrors.aliyun.com` | **200，TLS 0.32s** | HTTPS 通 |
| 下载 39KB 文件 | 稳定 **128 KB/s** | 出口限速 |
| `pip install pymysql`（容器内） | **成功** | pip 完全可用 |

**真相：服务器有外网，但出口限速约 128 KB/s，且 IPv6 完全不通。** 之前所有"失败"都源于：大包下载超时 + IPv6 优先导致的 connect 挂起 + curl 无 `-4`。

### 3.2 彻底解决方案（已落地）

| 策略 | 实施 |
|---|---|
| **小依赖在线装** | `pip -i https://mirrors.aliyun.com/pypi/simple/ --timeout 120 --retries 10`，容器内直装成功 |
| **大包离线 wheel** | 本机 `pip download --platform manylinux2014_x86_64` → 60MB 传上去 → `pip --no-index --find-links` |
| **CPU 兼容** | 服务器 Xeon 5320 **不支持 AVX2**，numpy 2.4.6（X86_V2 基线）无法 import → **钉死 numpy==1.26.4**（SSE 基线） |
| **依赖整树解析** | 放弃逐个猜传递依赖（multidict/click/litestar-htmx...），改为**容器内 pip install 全树 → docker commit 成 deps 层** |
| **分层镜像** | `:deps`（依赖层，已固化+验证）→ `:0.2.x`（应用层，秒级重建） |

**踩坑记录：**
1. musllinux wheel（alpine 下载的）装进 glibc（python:3.11-slim）失败 → 必须用 `--platform manylinux2014` 交叉下载
2. `uvicorn`/`pytest<9`/`redis<6` 等版本上限与新版本冲突 → 移除上限或直接删依赖
3. `pip download` 不带 `--platform` 时在 alpine 里只会拉 musllinux 版

### 3.3 对 TiKV/PG 议题的修正

外网实际可用后，**TiDB Operator 理论上可装**（需 ~2GB 镜像 × 128KB/s ≈ 4.5 小时，可行）。是否迁移重新变成开放决策，留给你：

| 选项 | 成本 | 收益 |
|---|---|---|
| 维持手工 StatefulSet | 0 | 已验证可用，缺自动编排 |
| 迁 TiDB Operator | ~5h 下载 + 迁移 | 自动扩缩容/升级/备份集成 |

## 4. 关键基础设施状态

```
TiDB:  PD 3/3(SS) · TiKV 3/3(SS,200Gi/副本) · TiDB 2/2 · TiFlash 1/1 —— 全 Running
存储:  7 PV 全 Bound（760Gi of 3T），Retain 策略
应用:  pdm-prod/python-diagnosis ×2 副本（:0.2.1），HPA 2–6
入口:  http://10.167.2.175:32231/pdm-api/* （Host: pdm-api.10.167.2.175.nip.io）
       ⚠ 必须带 /pdm-api 前缀：dify-catchall（无 host，/ Prefix）会吞掉其他路径
缓存:  L1 进程内(30s) + L2 Redis db3(120s) + /warmup 预热端点
```

**Ingress 踩坑记录**：dify 的 catch-all ingress 没配 host、占用了 `/` Prefix，会与任何无更长前缀的规则竞争。解法是 PdM 用专属长前缀 `/pdm-api` + regex rewrite `/$2`。另发现该集群 ingress 的 NodePort 对 keep-alive 连接有路由不一致（首请求 200 后续 404），测试端已用 `max_keepalive_connections=0` 规避，**生产接入需改用独立域名+独立 Ingress 或直连 NodePort**。
