## 2. 网络与工控安全架构（IEC 62443）

### 2.1 区域与管道（Zones & Conduits）

```
┌──────────── Zone 0：现场设备（SL1）────────────┐
│ 传感器 / 变送器 / 执行机构                      │
└───────────────────┬────────────────────────────┘
                    │ Conduit C1（4-20mA / IEPE，物理隔离）
┌───────────────────▼──── Zone 1：控制区（SL2）──┐
│ PLC / DCS / SIS（**本系统只读接入**）           │
└───────────────────┬────────────────────────────┘
                    │ Conduit C2（OPC UA，单向只读，白名单）
┌───────────────────▼──── Zone 2：边缘区（SL2）──┐
│ 边缘节点 K3s / 本地诊断 / 本地缓存              │
└───────────────────┬────────────────────────────┘
                    │ Conduit C3（数据闸，单向 OT→IT，仅特征值）
┌───────────────────▼──── Zone 3：平台区（SL3）──┐
│ K8s / 数据库 / Agent 运行时                     │
└───────────────────┬────────────────────────────┘
                    │ Conduit C4（HTTPS，OIDC）
┌───────────────────▼──── Zone 4：用户区（SL2）──┐
│ 办公网 PC / 移动端                              │
└────────────────────────────────────────────────┘
```

### 2.2 关键 SR（系统要求）落实

| IEC 62443-3-3 SR | 要求 | 本项目措施 |
|---|---|---|
| SR 1.1 | 身份识别与认证 | OIDC + MFA（管理角色强制） |
| SR 1.5 | 认证失败处理 | 5 次锁定 15 分钟 |
| SR 2.1 | 授权执行 | RBAC + 行级权限 |
| SR 3.1 | 通信完整性 | TLS 1.3 / mTLS |
| SR 4.1 | 信息保密 | 敏感字段 AES-256 |
| SR 5.1 | 网络分段 | 四区三管道 + 单向闸 |
| SR 6.1 | 审计日志 | 哈希链，WORM 存储 |
| SR 7.1 | 可用性 | 边缘自治 + 降级 |

### 2.3 硬性禁令（写进合同）

- ❌ 禁止从 IT 域向 OT 域发起主动连接（除运维白名单端口 + 跳板机）
- ❌ 禁止本系统向 PLC/DCS 写任何值（网络层 ACL + 应用层无写工具）
- ❌ 禁止在 OT 域部署可访问互联网的组件
- ❌ 禁止使用带外管理通道绕过审计

## 3. 数据分类分级

| 级别 | 定义 | 示例 | 存储 | 出厂 | 加密 |
|---|---|---|---|---|---|
| L4 极敏感 | 工艺配方、核心参数 | 压缩机运行曲线 | 厂内 | ❌ | 是 |
| L3 敏感 | 设备台账、故障记录、成本 | 备件价格、停机损失 | 厂内 | ❌ | 是 |
| L2 内部 | 诊断结论、方案卡 | HI、RUL | 厂内/私有云 | 脱敏后可 | 传输加密 |
| L1 公开 | 统计指标 | 设备总数 | 任意 | ✅ | 否 |

**默认规则：不确定就按高一级处理。**

### 3.1 脱敏规则（对外/上云前）

| 字段 | 脱敏方式 |
|---|---|
| 设备位号 | 哈希映射（`KA-101` → `A7F3`） |
| 人员姓名 | 保留姓氏 + `*` |
| 供应商 | 保留首字 |
| 金额 | 区间化（"4–5 万"） |
| 时间 | 保留相对时间（"T-14 天"） |

## 4. 生成式 AI 合规（GB/T 45654-2025 落点）

| 标准要求 | 本项目措施 | 证据 |
|---|---|---|
| 语料来源合法 | 仅使用企业自有维修手册、工单、标准文本；不使用爬取数据 | 语料清单 + 授权书 |
| 语料内容安全 | 入库前过内容安全过滤 | 过滤日志 |
| 知识产权 | 手册使用需授权；开源模型核对许可 | 许可清单（含 LimiX 风险） |
| 生成内容安全 | 输出过敏感词/越权检测 | 过滤规则 |
| 标识义务 | AI 生成内容标注"AI 辅助生成，需人工确认" | UI 水印 + 报告页脚 |
| 用户告知 | 首次使用弹出能力边界说明 | 截图 |
| 投诉与纠错 | 报告页"反馈"入口，72 小时响应 | 工单流程 |
| 日志留存 | 输入输出留存 ≥ 6 个月 | 日志策略 |

### 4.1 强制标识（不可关闭）

所有 AI 生成的报告、方案卡、对话回复，必须带：

```
⚠️ 本内容由 AI 辅助生成，结论基于 [数据时间窗] 的历史数据与 [模型版本]，
   不构成维修指令。任何停机、拆检、更换决策须由持证人员现场确认。
```

**这一条既是合规要求，也是责任边界。**

## 5. AI 治理体系（ISO/IEC 42001 精简落地）

### 5.1 治理架构

```
        ┌──────────────────────────────┐
        │   AI 治理委员会（季度）        │
        │   设备副总 / 设备科长 / CIO /  │
        │   安全负责人 / 算法负责人      │
        └───────────┬──────────────────┘
                    │
     ┌──────────────┼──────────────┬──────────────┐
     ▼              ▼              ▼              ▼
  模型准入      变更审批       事件响应       影响评估
  （新模型/      （提示词/      （误判/事故）  （新场景上线
   新版本）       判据/技能）                    前）
```

### 5.2 模型准入清单（Model Card 必填项）

| 项 | 要求 |
|---|---|
| 用途与边界 | 明确"能做什么/不能做什么" |
| 训练数据 | 来源、时间范围、样本量、标注方式 |
| 性能指标 | 在 Golden Set 上的召回/误报/RUL MAE |
| 已知失效模式 | 至少 5 条 |
| 许可 | 代码许可 + 权重许可（**分开写**） |
| 数据合规 | 是否含个人信息、是否可商用 |
| 可解释性 | 是否提供特征贡献 |
| 回滚方案 | 上一版本号 + 回滚耗时 |
| 责任人 | 模型 Owner |

### 5.3 变更管理（三类变更）

| 变更类型 | 示例 | 审批 | 灰度 |
|---|---|---|---|
| 判据变更 | 调整 BPFO 阈值 | 设备专家 + 架构师 | 1 台 → 全量 |
| 提示词变更 | 改会诊系统提示 | 算法负责人 | A/B 10% |
| 模型变更 | 换 RUL 模型 | 治理委员会 | 1 车间 → 全厂 |

**任何变更都必须可回滚，且回滚时间 < 15 分钟。**

## 6. 安全测试要求

| 类型 | 内容 | 频次 | 通过标准 |
|---|---|---|---|
| SAST | 代码静态扫描 | 每次提交 | 无高危 |
| 依赖扫描 | SCA / SBOM | 每日 | 无 CVSS ≥ 7.0 未修复 |

## 7. 审计链设计

### 7.1 审计记录内容

```json
{
  "audit_id": "AU-01J9Z...",
  "ts": "2026-10-21T06:31:12.482Z",
  "actor": {"type": "agent", "id": "agent-runtime-3", "on_behalf_of": "user:zhangsan"},
  "action": "tool.create_workorder_draft",
  "target": {"type": "recommendation", "id": "REC-20261021-0031"},
  "input_hash": "sha256:...",
  "output_hash": "sha256:...",
  "decision": "ASK→APPROVED",
  "approver": "user:lisi",
  "trace_id": "01J9Z...",
  "prev_hash": "sha256:...",
  "hash": "sha256:..."
}
```

### 7.2 哈希链

```
hash_n = SHA256(hash_{n-1} || canonical_json(record_n))
```

- 每日将当日最后 hash 写入独立的"锚点"表（可选：写入区块链/时间戳服务）。
- 任何篡改都会导致后续所有 hash 不匹配。

### 7.3 回放能力（对应 FR-802）

给定 `trace_id`，可完整重建：
1. 当时的数据快照（时间窗 + 质量分）
2. 计算出的特征值
3. 命中的规则/模型版本
4. LLM 的输入提示与输出
5. 人工确认记录
6. 最终动作与结果

**这是"AI 说错了谁负责"这个问题的技术答案：不是甩锅给 AI，而是能证明当时依据什么、谁签的字。**

## 8. 责任矩阵（RACI）

| 活动 | 设备科 | 算法团队 | 平台团队 | 安全 | 治理委员会 |
|---|---|---|---|---|---|
| 故障模式库维护 | **A/R** | C | I | I | I |
| 模型选型与上线 | C | **R** | C | C | **A** |
| 判据变更 | **A** | R | I | I | C |
| 方案卡确认 | **A/R** | I | I | I | I |
| 工单执行 | **A/R** | I | I | I | I |
| 安全事件响应 | C | C | R | **A** | I |
| 数据分类分级 | C | I | R | **A** | I |

> **A=批准，R=负责，C=咨询，I=知会。**
> 核心原则：**算法团队不批准自己的模型上线；设备科对判据负最终责任。**

## 10. AI 治理增补：三条新红线与 MCP 安全（2026-10-25）

### 10.1 Constitution 修正案 v1.1（三条红线，违反视同违反第二条）

| 条 | 内容 | 代码级落实 |
|---|---|---|
| 第十一条 | 判据变更必须走版本化发布通道，禁止直接改库 | `publish_group_rules`（version 递增）；`alert_rule` PK 含 version |
| 第十二条 | 技能禁止在线自生效，必须人工审批 | `load_active()` 只查 `status='APPROVED'` |
| 第十三条 | 世界模型输出必须带不确定性，样本不足返 null | `world.model.fit` 三边界；`trajectory` 每点含 lo/hi |

### 10.2 MCP 安全加固（针对 2025 生态漏洞）

| 风险 | 措施 | 验证 |
|---|---|---|
| 工具投毒 | 工具白名单（只允许注册表内 12 个） | `test_tool_allowlist_rejects_unregistered` |
| SSRF | 资源 URI 白名单，不接受任意 URL | `test_resource_uri_whitelist` |
| 令牌/租户泄露 | 四类方法均强制校验 `X-Tenant-Id` | `test_missing_tenant_rejected_on_all_methods` |
| 审计缺失 | 每次 `tools/call` 落 `audit_log` | `test_audit_written_on_tool_call` |
| 数据外泄 | 不提供 sampling（边缘场景尤其） | 能力声明中无 sampling |

### 10.3 智能体可追责

- 每次计划执行产出 `trace_id` + 状态序列（IDLE→GATE→ACT→OBSERVE→VERIFY→DONE）
- 关键操作（写/关闭告警/点检提交）必须过 `PermissionGate`，未批准即 PENDING_APPROVAL
- 遥测失败不阻塞业务，但**降级必须显式**（`transport_degraded`、`degraded=true`）

### 10.4 合规映射更新

| 标准 | 新增符合点 |
|---|---|
| GB/T 45654-2025 模型安全 | 模型版本注册 + 漂移检测 + 反馈闭环 |
| ISO/IEC 42001 AI 管理体系 | 技能审批管线（人机共决）+ 冻结回滚 |
| IEC 62443 | MCP 工具白名单与调用审计 |
