## 1. ISO 13374 六功能块在本项目的落地

| 块 | 职能 | 本项目实现 | 输入 | 输出 | 标准依据 |
|---|---|---|---|---|---|
| **DA** Data Acquisition | 采集 | `ingest-gateway` | 模拟量/数字量/波形 | 原始样本流 | ISO 13374-2 |
| **DM** Data Manipulation | 处理 | `feature-engine` | 原始样本 | 清洗/对齐/特征 | ISO 13373-1 |
| **SD** State Detection | 状态检测 | `diagnosis-engine` | 特征 | 异常/正常 + 事件 | ISO 20816 / GB/T 19873 |
| **HA** Health Assessment | 健康评估 | `diagnosis-engine` | 特征 + 历史 | HI 0–100 + 四级 | ISO 13374-1 §6 |
| **PA** Prognosis Assessment | 预后 | `prognosis-engine` | HI 序列 + 工况 | RUL 分布 | ISO 13374-1 §7 |
| **AG** Advisory Generation | 建议生成 | `agent-runtime` + `decision-service` | 诊断+预后+约束 | 报告 / 方案卡 | ISO 13374-1 §8 |

> **架构价值：** 六块是"信息处理职能"，不是"软件模块"。我们把它做成六个**契约接口**，任何一块的实现可替换（这正是 P6 单点可替换原则的落地）。

```python
# 契约示意（Python Protocol，非最终代码）
class StateDetector(Protocol):
    def detect(self, features: FeatureFrame, ctx: AssetContext) -> list[StateEvent]: ...

class HealthAssessor(Protocol):
    def assess(self, events: list[StateEvent], hist: History) -> HealthIndex: ...

class Prognosor(Protocol):
    def predict(self, hi_series: Series, regime: Regime) -> RULDistribution: ...

class Advisor(Protocol):
    def advise(self, diag: Diagnosis, constraints: Constraints) -> RecommendationCard: ...
```

## 2. 数据接入与预处理（DA / DM）

### 2.1 采样参数基线

| 物理量 | 采样率 | 窗长 | 触发方式 | 备注 |
|---|---|---|---|---|
| 振动加速度 | 25.6 kHz | 1 s（25600 点） | 定时（1 次/小时）+ 阈值触发 | 覆盖 10 kHz 分析带宽 |
| 振动速度 | 由加速度积分 | 同上 | 同上 | ISO 20816 用速度 RMS |
| 温度 | 1 Hz | 60 s 均值 | 定时 | — |
| 电流 | 1–10 kHz | 1 s | 定时 | 用于电气故障特征 |
| 转速 | 1 Hz | — | 定时 | 阶次分析必需 |
| 油液（可选） | 事件驱动 | — | 人工录入 | 磨粒计数 |

**抗混叠：** 模拟低通截止 ≥ 0.4×fs，数字滤波 ≥ 8 阶 Butterworth。
**加窗：** 稳态用 Hanning；瞬态/冲击用矩形或指数窗。

### 2.2 数据质量门（DQ Gate）

每条数据入库前必须通过 5 项检查，输出质量分 `Q ∈ [0,100]`：

| 检查 | 判据 | 扣分 |
|---|---|---|
| 缺失 | 应有样本数 vs 实到 | 按比例扣至 0 |
| 超量程 | 超出传感器量程 ±5% | 每点 −2 |
| 冻结值 | 连续 30 个样本方差 = 0 | −30 |
| 时间戳跳变 | Δt > 3×标称周期 | 每处 −10 |
| 单位/量纲 | 与元数据不符 | −50（直接隔离） |

**规则：`Q < 60` 的数据不参与 SD/HA，仅存档。** 这是防误报的第一道闸。

### 2.3 统一时基

- 全链路 UTC（epoch ms），展示层转本地时区。
- 边缘节点 NTP 同步，偏差 > 50 ms 触发告警。
- 多源对齐采用"最近邻 + 线性插值"，插值跨度 > 2×标称周期则标记 `ALIGNED_LOW_CONF`。

## 3. 特征工程（DM）

### 3.1 时域特征

| 特征 | 公式 | 诊断意义 |
|---|---|---|
| RMS | √(1/N Σx²) | 能量，ISO 20816 主判据（速度 RMS） |
| 峰值 Peak | max\|x\| | 冲击 |
| 峰峰值 PP | max−min | 振动总量 |
| 峭度 Kurtosis | E[(x−μ)⁴]/σ⁴ | 早期冲击（>4 提示） |
| 偏度 Skewness | E[(x−μ)³]/σ³ | 不对称（摩擦/松动） |
| 峰值因子 Crest | Peak/RMS | 冲击性 |
| 裕度因子 Clearance | Peak/(1/N Σ√\|x\|)² | 磨损 |
| 脉冲因子 Impulse | Peak/(1/N Σ\|x\|) | 早期点蚀 |

### 3.2 频域特征

| 特征 | 方法 | 用途 |
|---|---|---|
| 频谱 | FFT（Hanning，1024/2048 线） | 主频识别 |
| 速度频谱 | 加速度积分 → 速度 | ISO 20816 判级 |
| 包络谱 | Hilbert 变换 → 包络 → FFT | 轴承早期故障（共振解调） |
| TOP5 谱峰 | 峰值搜索 + 谐波聚类 | 特征频率匹配 |
| 边频带 | 主频 ± n×fr | 齿轮/偏心 |
| 阶次谱 | 等角度重采样 + FFT | 变转速工况 |
| 倒频谱 | IFFT(log\|FFT\|) | 周期冲击分离 |
| 小波包能量 | db4，3 层分解 | 非稳态 |

### 3.3 轴承特征频率（核心判据）

```
fr  = 转速 / 60                          （转频 Hz）
BPFO = (n/2)·fr·(1 − (d/D)·cosα)        外圈通过频率
BPFI = (n/2)·fr·(1 + (d/D)·cosα)        内圈通过频率
BSF  = (D/2d)·fr·(1 − ((d/D)·cosα)²)    滚动体
FTF  = (fr/2)·(1 − (d/D)·cosα)          保持架

n=滚珠数, d=滚珠直径, D=节径, α=接触角
```

| 故障 | 频谱特征 | 包络谱特征 |
|---|---|---|
| 外圈 | BPFO 及谐波，幅值随载荷 | BPFO 明显，边带少 |
| 内圈 | BPFI 及谐波，**带 fr 边带** | BPFI + fr 边带 |
| 滚动体 | BSF，**带 FTF 边带** | BSF ± FTF |
| 保持架 | FTF（低频），常伴 1×/2× 谐波 | FTF 弱 |
| 不平衡 | 1× 主导，相位稳定 | — |
| 不对中 | 2× 显著（>1× 的 50%） | — |
| 松动 | 多阶谐波（1×,2×,3×…）+ 底噪抬升 | — |
| 齿轮啮合 | GMF 及边带（±fr） | — |

> **工程提醒：** 上表是"教科书特征"，现场必须叠加**设备结构固有频率**与**管路/基础共振**，否则会把共振峰误判为故障频率。故障模式库中每个模式必须绑定"排除条件"。

### 3.4 特征选择与降维

- 初始特征 ~120 维 → 相关性过滤（\|r\|>0.95 去冗余）→ 方差过滤 → 模型内选择（L1/树模型重要性）。
- **保留可解释性优先**：最终进入诊断的特征 ≤ 25 个，每个必须有物理含义。
- 禁止"黑箱 500 维特征 + 深度模型"作为主链路——工业场景要能解释。

## 4. 状态检测（SD）

### 4.1 三级判据体系

```
Level 1  绝对阈值（标准/厂商）—— 保底，防漏
Level 2  相对基线（自学习）—— 主判据，适应个体差异
Level 3  趋势斜率（变化率）—— 早期预警
```

**为什么需要三级：** 绝对阈值会漏掉"本来就振动大但一直稳定"的设备；相对基线会漏掉"突然劣化但仍在阈值内"的设备；趋势斜率能捕捉"缓慢但持续"的劣化。

### 4.2 绝对阈值（ISO 20816 分区）

以 ISO 20816-3（15 kW–1 MW 工业机器）为例，速度 RMS 分区：

| 分区 | 范围 | 含义 | 本项目映射 |
|---|---|---|---|
| A | 新机 | 优 | 绿 |
| B | 可长期运行 | 良 | 绿/黄 |
| C | 不宜长期运行 | 注意 | 橙 |
| D | 可能损坏 | 危险 | 红 |

> 具体限值按机型/功率/安装方式查表，**不得使用通用值**。GB/T 6075 等同采用 ISO 20816 系列。

### 4.3 相对基线（自学习）

```
baseline = median(特征值) over 学习窗（默认投运后 30 天，且工况在额定 70–110%）
σ_robust = 1.4826 × MAD
异常分数 z = (x − baseline) / σ_robust

告警规则：
  z > 3   且持续 ≥ 30 min  → 黄
  z > 5   且持续 ≥ 30 min  → 橙
  z > 8   或 突增 > 100%   → 红
```

**3σ 的工程修正：** 工业数据非高斯、有工况漂移，必须用 **MAD（中位数绝对偏差）** 而非标准差，且按工况分箱（负载/转速/环境温度）建基线。这是原文"3σ 异常检测"必须打的补丁。

### 4.4 趋势斜率

```
slope = Theil-Sen 估计（鲁棒，抗离群）
劣化速率 = slope / baseline  （%/天）
加速判据：近 7 天斜率 > 前 30 天斜率 × 2
```

## 5. 健康评估（HA）

### 5.1 HI 构造（可解释版）

```
HI = 100 × Π(1 − w_i · s_i)

其中 s_i ∈ [0,1] 为第 i 个维度归一化劣化度：
  s_vib  振动烈度（相对基线与绝对阈值取大）
  s_imp  冲击/峭度
  s_temp 温升（相对环境）
  s_curr 电流特征（MCSA）
  s_trend 劣化速率
w_i 为权重，Σw_i = 1，默认 (0.35, 0.20, 0.15, 0.15, 0.15)

约束：
· 任一 s_i = 1 → HI = 0（单维度致命即整体致命）
· 缺失维度时按剩余维度权重重归一，并标注"降级"
```

**为什么用乘积而非加权和：** 加权和会被"其他维度都很好"稀释掉单一致命故障；乘积形式符合"短板效应"，且单调、可解释。

### 5.2 四级色与动作

| 等级 | HI | 含义 | 默认动作 | 响应时限 |
|---|---|---|---|---|
| 绿 | 80–100 | 健康 | 常规巡检 | — |
| 黄 | 60–79 | 关注 | 加密监测（1 次/小时） | 7 天 |
| 橙 | 40–59 | 劣化 | 进入会诊，准备窗口 | 72 小时 |
| 红 | 0–39 | 危险 | 立即会诊，建议停机检查 | 4 小时 |

### 5.3 可解释性输出

每次 HI 必须返回贡献度分解：

```json
{
  "hi": 47,
  "level": "orange",
  "contributions": [
    {"dim": "vib_rms", "s": 0.62, "w": 0.35, "delta": -21.7, "evidence": "DE_H 速度RMS 4.8mm/s (Zone C)"},
    {"dim": "kurtosis", "s": 0.55, "w": 0.20, "delta": -11.0, "evidence": "峭度 5.2 (>4 阈值)"},
    {"dim": "trend", "s": 0.40, "w": 0.15, "delta": -6.0, "evidence": "近7天 +3.2%/天"}
  ],
  "degraded": false
}
```

## 6. 预后（PA）

### 6.1 三条技术路线（并存，按场景选用）

| 路线 | 方法 | 适用 | 数据需求 | 可解释性 |
|---|---|---|---|---|
| **A 物理退化模型** | 指数/幂律退化拟合 + 失效阈值 | 单一退化机理、数据少 | 低（≥ 30 个历史点） | 高 |
| **B 统计学习** | 梯度提升 / 随机森林 / LimiX | 多特征、样本充足 | 中（≥ 200 例） | 中 |
| **C 时序深度模型** | LSTM / TCN / PatchTST / 时序基础模型 | 长序列、复杂模式 | 高 | 低 |

**默认策略：A 为基线（永远可用），B 为挑战者，C 为实验。** 三者在同一评测集上对比，择优上线，其余保留为 fallback。

### 6.2 路线 A：指数退化（基线实现）

```
HI(t) = HI_0 · exp(−λ t)     →   ln HI 对 t 线性回归
失效阈值 HI_f = 40（橙线）
RUL = (ln HI_f − ln HI_now) / (−λ)
置信区间：对 λ 的估计做 bootstrap（1000 次）取 P10/P50/P90
```

### 6.3 OOD 与外推风险

```python
# 工况分布校验（示意）
if not in_training_envelope(regime, envelope):
    return RUL(trend_only=True, warning="工况超出训练分布，仅给趋势方向")
```

**触发 OOD 的典型情况：** 转速偏离 ±20%、负载偏离 ±30%、环境温度偏离 ±15℃、更换了传感器/改变安装位置。

### 6.4 RUL 输出契约

```json
{
  "rul_days": {"p10": 11, "p50": 19, "p90": 34},
  "model": {"name": "exp-degradation", "version": "1.2.0", "trained_on": "2025-06~2026-09"},
  "confidence": 0.72,
  "regime_valid": true,
  "ood_warning": null,
  "assumptions": ["负载稳定在 85%", "未更换轴承", "润滑状态不变"]
}
```

**强制要求：`assumptions` 字段不可为空。** 没有假设声明的 RUL 是不可用的 RUL。

## 7. 模型选型与 LimiX 风险评估

### 7.1 候选模型对比

| 模型 | 类型 | 许可 | 参数量 | 优势 | 风险 | 结论 |
|---|---|---|---|---|---|---|
| **经典特征 + 树模型** | 监督 | 自有 | — | 可解释、样本需求低、无许可风险 | 上限有限 | ✅ **基线** |
| **LimiX（初代）** | 结构化基础模型 | Apache 2.0 | 16M | 零样本、因果+稳定学习 | 需验证工业适配 | ⚠️ 挑战者 |
| **LimiX-2** | 结构化基础模型 | **非商用** | — | 性能更强 | **商用需授权** | ❌ 生产禁用 |
| **LimiX-2M** | 轻量 | 需核实 | 2M | 可边缘部署 | 同上 | ⚠️ 需法务确认 |
| **时序基础模型（PatchTST/Chronos 类）** | 预训练 | 多为 Apache/MIT | 各异 | 少样本 | 推理成本 | ⚠️ 实验 |
| **物理模型（ISO 判据）** | 规则 | 标准公开 | — | 零训练、可审计 | 覆盖率低 | ✅ **保底** |

### 7.2 许可风险处置（必须写进合同/方案）

| 场景 | 处置 |
|---|---|
| POC / 内部验证 | 可用 LimiX-2（非商用允许研究） |
| 交付客户生产 | **禁止**使用非商用权重；改用经典模型或采购商业授权 |
| 若客户坚持用 LimiX-2 | 需取得版权方书面商用授权，并写入交付清单 |

> **这一条是原文没有覆盖的硬伤。** 开源不等于可商用，权重许可与代码许可是两件事。

### 7.3 模型管理

| 项 | 要求 |
|---|---|
| 版本 | 语义化版本 + 数据集指纹 + 代码 commit |
| 注册 | 模型注册表（MLflow 或自建），记录指标与许可 |
| 灰度 | 按设备/车间灰度，支持一键回滚 |

## 8. 数据集治理

### 8.1 数据集分层

| 数据集 | 内容 | 规模目标 | 用途 |
|---|---|---|---|
| **Golden Set** | 已确认故障案例（含专家标注） | ≥ 60 例 | 验收、回归 |
| **Replay Set** | 连续 3 个月全量数据 | 20 台 | 误报率评估 |
| **Synthetic Set** | 仿真/注入故障 | 不限 | 冷启动 |
| **Red Team Set** | 提示注入/越权/诱导 | ≥ 20 例 | 安全测试 |
| **OOD Set** | 工况越界样本 | ≥ 30 例 | 鲁棒性 |

### 8.2 标注规范

| 字段 | 要求 |
|---|---|
| 故障类型 | 取自故障模式库（受控词表），禁止自由文本 |
| 严重度 | 轻微/中等/严重/致命 |
| 确认方式 | 拆检报告 / 更换记录 / 专家判定（三选一，须附证据） |
| 标注人 | 双人独立标注，Kappa ≥ 0.7 方可用 |
| 时间窗 | 故障发生前后各 30 天 |

**标注质量是模型上限。** 没有拆检报告的"故障样本"只能算"疑似"，不得进入 Golden Set。

### 8.3 数据血缘

```
raw_waveform(sha256) → feature_set(v{n}) → training_run(id) → model(v{x.y.z}) → diagnosis(id) → recommendation(id)
```

任一环节可正向追溯、反向定位。这是"证据可回放"（P2）的数据基础。
