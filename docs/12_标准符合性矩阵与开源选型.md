## 2. 开源项目选型评估

### 2.1 原文 5 个项目的核实结论

| # | 项目 | 层 | 核实情况 | 许可 | 生产可用 | 结论 |
|---|---|---|---|---|---|---|
| 1 | **Open supOS** | L1 数据底座 | 真实存在，蓝卓开源工业 AI 数据底座，宣称 70+ 协议、5,000 点/秒、统一命名空间 + Factory Agent | 社区版（需核实具体条款） | ⚠️ 中 | **参考实现**，不锁定；优先验证协议覆盖与社区活跃度 |
| 2 | **LimiX** | L2 结构化模型 | 真实存在（arXiv 2509.03505）；LimiX-2M（2025-11）、LimiX-2（2026-09） | 初代 Apache 2.0；**LimiX-2 权重非商用** | ❌ 商用受限 | **POC 可用，生产禁用**（除非获授权） |

### 2.3 许可证风险矩阵（必须让法务过一遍）

| 许可类型 | 组件 | 风险 | 处置 |
|---|---|---|---|
| **非商用权重** | LimiX-2 | 🔴 高 | 生产禁用；需授权 |
| **AGPL** | TDengine 社区版 | 🟠 中 | 若以 SaaS 形式对外提供服务需开源；**内部使用通常无碍，但需法务确认** |
| **Apache 2.0** | 多数组件 | 🟢 低 | 保留 NOTICE |
| **MIT** | LiteLLM 等 | 🟢 低 | 保留版权声明 |
| **社区版功能限制** | supOS CE、EMQX CE | 🟠 中 | 确认功能边界，避免上线后发现缺关键能力 |

> **一条铁律：开源项目的"代码许可"和"模型权重许可"是两件事。** LimiX 就是典型：代码 Apache 2.0，但 LimiX-2 权重非商用。很多团队栽在这。

## 3. 方法论符合性

| 方法 | 在本项目的落地 | 不落地的部分（及原因） |
|---|---|---|
| **SDD** | specs/ 为单一真相源；constitution → spec → plan → tasks | 不做全自动代码生成（工业场景需人工 review） |
| **TDD** | 核心算法（特征/HI/RUL/权限）严格 TDD | UI 层不强制（成本高收益低） |
| **BDD** | 关键业务场景 Gherkin 化 | 不追求 100% 覆盖（探索性场景难写） |
| **ATDD** | 三方评审 + 验收标准前置 | — |
| **TOGAF ADM** | A/B/C/D/E/F 阶段映射 | 不做完整 ADM 全周期（项目级裁剪） |
| **Harness 工程** | 10 组件全落地 | 不做"模型自主编排"（工业要可预测） |
| **Hermes 式自进化** | 技能提炼 + 记忆沉淀 | **禁止在线自生效**（改判据必须走变更管理） |
| **敏捷** | 双周迭代、站会、回顾 | 不做纯 Scrum（阶段 Gate 不可省） |

## 4. 与原文的差异对照（供评审时对照阅读）

| 维度 | 原文 | 本方案 | 差异原因 |
|---|---|---|---|
| 分层依据 | 技术栈五层 | 技术五层 × ISO 13374 六块 | 标准可审计 |
| 交付顺序 | 按层装配 | 按 Gate 推进（数据先行） | 原文也说"越不智能越先做"，本方案把它制度化 |
| LimiX | 推荐为核心 | 降级为挑战者 + 许可风险 | 权重非商用 |
| 交互层 | MCP 服务端 | MCP + Harness 运行时 | 裸 MCP 缺权限/审计/护栏 |
| 决策层 | 四角色 + 协调者 | 四角色 + 协调者 + **独立 Evaluator** | 防自说自话 |
| 边缘层 | OpenClaw 做原型 | 同（且明确生产用标准 API） | 一致 |
| 验收 | 6 项清单 | 42 项 + 分级 + 签字表 | 可执行 |
| 智能体工程 | 未涉及 | Harness 10 组件 + 失败模式表 | 2026 年工程共识 |
| 规格管理 | 未涉及 | SDD 三件套 + EARS | AI 时代的可追溯性 |

## 6. 先进技术的方法论符合性与选型（2026-10-25）

### 6.1 概念 → 标准/实践映射

| 概念 | 业界依据 | 本项目落地 | 取舍 |
|---|---|---|---|
| Agent Harness | `Agent = Model + Harness`（2026 工程范式）；Anthropic context engineering（2025-09） | `app/harness/` 七组件 | 自研，不用 LangGraph/CrewAI（需权限门/Stop Hook 一等公民） |
| MCP | Anthropic 2024-11 提出，2025-12 移交 Linux Foundation AAIF | `app/mcp.py`，协议 2025-03-26 | 自实现 JSON-RPC，不装 SDK（内网出口受限） |
| A2A | Google 2025-04 发布，2025-06 捐 Linux Foundation，2026-08 入 AAIF | `app/a2a/` Agent Card + tasks | 只实现核心（tasks），不做 streaming/push |
| Hermes 式记忆 | Nous Research 闭环学习（任务→技能→记忆→复用） | `app/memory/` 三层记忆 + 受控技能 | **禁止在线自生效**（工业红线） |
| 世界模型 | ICCV 2025 高斯世界模型等 | `app/world/` L1 统计模型 | 先可解释统计模型，L2 神经模型预留 |
| OTel GenAI | CNCF GenAI SIG 语义约定（2024-04 起） | `app/harness/otel.py` 三层 span | 手动 span，不引 SDK |

### 6.2 不引入的组件及理由（可复核）

| 组件 | 不引入理由 |
|---|---|
| LangGraph / CrewAI | 抽象隐藏权限门与 Stop Hook；工业审计需要显式控制点 |
| MCP 官方 SDK | 依赖链长，内网出口 128KB/s；HTTP 传输层即 JSON-RPC |
| LiteLLM / Milvus | 本期无 LLM 调用；世界模型走统计路线，L2 时再引入 |
| Alembic | TiDB 方言支持不完整；用 `tools/migrate.sh` + checksum 幂等替代 |
