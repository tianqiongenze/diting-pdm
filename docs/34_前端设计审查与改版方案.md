## 二、问题清单（按严重度排序）

### P0 · 结构性

**① 信息密度与首屏价值错配**
表格吃掉 1112px，三个核心功能面板（趋势/诊断/日志）被推到首屏之外且初始为空。
用户打开页面第一眼看到的是"一大片表格 + 三个空壳"，**第一屏没有任何可行动的洞察**。

**② 空面板占据 60% 面板面积**
三个面板各 85px，只放了一行灰字提示。空状态没有设计——不是"留白"，是"浪费"。

**③ 无数据行稀释有效信息（75%）**
20 行里 15 行是"未评价 / - / 空条"。真正有健康度的只有 5 行，被 3 倍的噪音淹没。
视觉上表格看起来"很长很满"，实际信息密度极低。

**④ 零数据可视化**
一个 PdM（预测性维护）系统，全页只有一条 4px 高的进度条。
缺少：趋势、分布、构成、相关性、拓扑——这些才是运维决策的依据。

### P1 · 视觉体系

**⑤ 视觉层级扁平**
KPI 卡与内容面板用完全相同的白底 + 1px 边框 + 同圆角，没有主次。
KPI 数字（20/1/0/1/2）与内容表格的视觉权重相当，用户不知道先看哪。

**⑥ KPI 卡语义混乱**
- 6 个卡等宽等重，但"事件传输 pulsar"是**文字**不是数字，破坏了数字节奏
- 语义色不一致：红色卡的数字是红的，橙色卡的数字是灰的（因为值是 0）
- 无趋势指示（环比）、无目标值、无迷你走势

**⑦ 色彩语义未成体系**
`--red/--orange/--yellow/--green` 只用在等级徽章上，
没有贯穿到：KPI 卡左边框、表格行左色条、图表配色、告警等级。
结果：色彩"点缀"而非"语言"。

**⑧ 操作日志是黑色终端块**
在浅色体系里一块纯黑，视觉上像"错误"或"未加载"。应改为浅色日志流 + 级别色点。

### P2 · 交互与可扩展

**⑨ 无导航，无法扩展**
单页单 header，加一个功能就要改整个 HTML 结构。
要承载"更多前端和大屏"，必须先有路由与导航壳。

**⑩ 无响应式、无动效**
固定 1236px 宽内容区；无 hover 反馈、无进入动效、无数字滚动。
在 1920 投屏和 1366 笔记本上观感一致（都不合适）。

## 三、改版方案

### 3.1 双主题设计系统

| 主题 | 用途 | 基调 |
|---|---|---|
| **深色大屏**（Screen） | 监控中心投屏、汇报演示 | 近黑蓝底 + 天青主色 + 发光 |
| **浅色管理台**（Console） | 日常操作、工单处理 | 冷灰底 + 靛蓝主色 + 轻阴影 |

统一 Token（两套主题共享语义，仅换色值）：

```
色板
  语义  红 #F43F5E / 橙 #FB923C / 黄 #FACC15 / 绿 #22C55E
  主色  深色 #38BDF8（天青）  浅色 #1D4ED8（靛蓝）
  中性  7 级灰阶（bg → panel → line → sub → text → strong → inverse）

字号  11 / 12 / 13 / 14 / 16 / 20 / 28 / 36 / 48 / 64
间距  4 的倍数（4/8/12/16/20/24/32/40）
圆角  6（小）/ 10（中）/ 14（大）/ 999（胶囊）
阴影  3 级（sm/md/glow）
```

### 3.2 页面架构（5 个视图）

| 视图 | 路由 | 主题 | 定位 |
|---|---|---|---|
| **大屏驾驶舱** | `#/screen` | 深色 | 1920×1080 全屏，一屏看全厂 |
| 运营看板 | `#/dashboard` | 浅色 | 日常巡检入口 |
| 设备台账 | `#/assets` | 浅色 | 2400 台检索、筛选、抽屉详情 |
| 工单看板 | `#/cards` | 浅色 | 方案卡按状态分栏（Kanban） |
| 诊断工作台 | `#/diagnose` | 浅色 | 输入→诊断→雷达图→证据链 |

### 3.3 手写 SVG 图表（零 CDN，内网必可用）

| 图表 | 用在哪 | 说明 |
|---|---|---|
| 环形进度环 | 大屏 KPI | 4 段弧表示红/橙/黄/绿占比，中心大数字 |
| 面积折线 | 趋势 | 渐变填充 + 网格 + 悬停点 |
| 雷达图 | 诊断工作台 | 五维（振动/温度/电流/趋势/工艺） |
| 横向条形 | 关键度分布 | A/B/C 三色条 |
| 健康矩阵 | 大屏 | 2400 台抽样点阵，颜色=等级 |
| 迷你 sparkline | 表格行内 | 12×28px 微走势 |
| 滚动告警 | 大屏底部 | 无缝滚动 ticker |

**为什么不用 ECharts**：内网无法访问 CDN，把 ECharts 内联会让单文件膨胀到 1MB+，
且 ConfigMap 有大小限制。手写 SVG 体积可控（每个图表 < 2KB 代码），
且完全贴合设计系统配色。

### 3.4 关键改进对照

| 原问题 | 改法 |
|---|---|
| 表格占满首屏 | 大屏改为「环 + 矩阵 + 趋势 + 分布」四象限；管理台表格限高 8 行 + 内部滚动 |
| 空面板 60% | 空状态改为「图标 + 引导文案 + 一键快捷操作」；诊断/趋势默认加载首台设备 |
| 无数据行 75% | 增加「仅看有健康度」筛选，默认开启；无数据行折叠为计数提示 |
| 零可视化 | 6 类图表 + sparkline |
| 层级扁平 | KPI 用大数字 + 语义左边框 + 环比；内容面板降一级底色 |
| pulsar 混在数字里 | 移出 KPI 区，改为顶部状态条上的一个 LED 指示 |
| 日志黑块 | 浅色日志流 + 级别色点 + 等宽时间戳 |
| 无导航 | 左侧图标导航 + 顶部面包屑，hash 路由 |

## 五、验收标准

| 项 | 标准 |
|---|---|
| 首屏信息密度 | 大屏 1920×1080 一屏内呈现 ≥ 5 类信息（KPI/分布/趋势/告警/拓扑） |
| 空状态 | 每个面板无数据时都有图标 + 引导，无纯灰字 |
| 色彩语义 | 四级健康色贯穿 KPI / 表格 / 图表 / 徽章 |
| 图表 | ≥ 6 类，全部 SVG 手写，零外链 |
| 响应式 | 1366 / 1600 / 1920 三档均无横向滚动 |
| 性能 | 首屏可交互 < 1.5s（内网） |
| 功能回归 | 浏览器测试 48 项 + E2E 66 项全绿 |
