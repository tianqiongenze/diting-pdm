## 2. 组织与租户模型

### 2.1 组织树（多租户基础）

```
雅迪集团（tenant root）
├─ 基地 A（tenant: site-a）┐
│   ├─ 车架冲焊车间          │ 一级域：厂内
│   │   ├─ 产线 L1
│   │   │   └─ 工位 ST01 → 设备 → 部件 → 测点
│   │   └─ 产线 L2
│   ├─ 烤漆车间
│   ├─ 注塑车间
│   ├─ 电机制造车间
│   └─ 总装车间
├─ 基地 B（tenant: site-b）
├─ ... ×20
└─ 供应商域（tenant: supplier-xxx）┐
    ├─ Tier1 轮胎                    │ 二级域：跨组织
    ├─ Tier1 电机                    │ 只读 + 上报，权限最小
    └─ Tier1 电池                    │
```

### 2.2 三类租户的能力差异

| 能力 | 集团 | 基地 | 供应商 |
|---|---|---|---|
| 跨基地对标分析 | ✅ | ❌ | ❌ |
| 本基地全域 | ✅ | ✅ | ❌ |
| 本车间数据 | ✅ | ✅ | ❌ |
| 本厂设备健康 | ❌ | ❌ | ✅（仅自己的） |
| 诊断问答 | ✅ | ✅ | ✅（仅自己的） |
| 方案卡确认 | ✅ | ✅ | ❌ |
| 工单创建 | ✅ | ✅ | ❌ |
| 数据上报（质量/设备状态） | — | — | ✅ |
| 故障模式库查看 | ✅ | ✅ | 脱敏版 |

### 2.3 租户隔离的四个层面（缺一即破）

| 层 | 机制 | 落地 |
|---|---|---|
| 身份 | OIDC + tenant claim | `tenant_id` 写入 JWT |
| 网关 | 字段级 + 行级权限 | GraphQL directive + 服务端 RLS |
| 数据 | PostgreSQL RLS + 分区键 | `tenant_id` 强制，连接池强制 `SET LOCAL app.tenant`；TiDB 读模型无 RLS，用 TenantQueryBuilder + 断言补偿（docs/17 §5） |
| 消息 | Pulsar tenant/namespace | `tenant/site-a/*`，生产需 `authorization` 授权 |
| 集群 | Namespace + NetworkPolicy | `pdm-site-a` 或统一 `pdm-prod` + 标签隔离 |

> **Pulsar 的 tenant/namespace 模型天然匹配多基地场景**，这是选择它而不是 Kafka 的决定性理由之一（详见 docs/16 §4）。

## 3. 电动车制造设备域（Sub-Domain）

### 3.1 工艺链与关键设备

电动车两轮制造的典型工艺链，以及各环节的预测性维护价值点：

| 工序 | 关键设备 | 主要故障模式 | 维护代价特征 | 优先级 |
|---|---|---|---|---|
| **车架冲压/焊装** | 冲压机、点焊机器人、弧焊机器人 | 焊钳磨损、减速机齿轮断齿、伺服电机轴承、焊臂变形 | 停线即停产，损失线性 | **P0** |
| **烤漆** | 喷涂机器人、烤漆炉、风机 | 机器人齿轮箱、风机动不平衡、炉温风机 | 环保风险高 | **P0** |
| **注塑/塑料件** | 注塑机、机械手 | 液压系统泄漏、螺杆磨损、射台轴承、哥林柱 | 换模损失大 | **P0** |
| **电机制造** | 绕线机、嵌线机、转子压装 | 主轴轴承、伺服电机、气动元件 | 精度下降→质量事故 | **P1** |
| **控制器/SMT** | 贴片机、回流焊 | 贴片头磨损、伺服轴、风机 | 高价值设备 | **P1** |
| **电池 PACK** | 点焊机、激光焊、检测设备 | 焊头、激光器、传送机构 | 安全关键（热失控） | **P0** |
| **总装** | AGV/输送链、拧紧工具、压装机 | 输送电机、拧紧枪、升降机构 | 直接影响节拍 | **P0** |
| **整车下线检测** | 胎压/制动/灯光检测台 | 传感器、执行机构 | 交付节点 | P2 |

### 3.2 与通用旋转机械的差异（决定算法不能照搬）

| 差异 | 说明 | 对方案的影响 |
|---|---|---|
| **变速工况多** | 输送链、AGV、变频风机频繁启停 | 阶次分析（order tracking）必须是标配，固定频率 FFT 不够 |
| **重载冲击** | 冲压、压装的瞬态冲击 | 需要触发式波形（阈值/事件触发），不能只靠定时采样 |
| **大量伺服系统** | 谐波丰富，电磁噪声大 | 排除条件库要扩充伺服特征，否则误报率高 |
| **产线节拍敏感** | 停机必须排产确认 | 方案卡的"窗口协商"必须与 MES 深度集成 |
| **追溯要求** | 部分件需追溯拧紧工艺数据 | 事件溯源天然契合（这是汽车行业迁移的关键能力） |
| **大量气动元件** | 换向阀、气缸 | 非旋转部件，需声音/压力/流量特征 |

> **这一节是"预留迁移到汽车"的技术根基**：总装拧紧追溯、IATF 16949 的过程控制，本质上就是"带时间戳的设备事件链"。我们用事件溯源做诊断证据链，同一套基础设施可以直接支撑质量追溯。

### 3.3 关键设备分级（借鉴 ISO 55000 / GB/T 33172）

```
关键度 A（致命）：停线即停产，或涉安全/环保
关键度 B（重大）：降产能或质量风险
关键度 C（一般）：冗余或可离线

分级输入：停产损失/小时、是否瓶颈工序、是否有冗余、安全影响、更换周期
分级结果驱动：会诊优先级、告警 SLA、监测密度
```

## 4. 三大业务场景（价值分级）

### 场景 1（P0）总装线节拍保障：不停线就是最大收益

- **问题**：总装线 AGV/输送/拧紧设备故障，直接停线，节拍损失按分钟算。
- **方案**：输送电机 + 拧紧工具 + AGV 驱动轮的状态监测，异常前 5–14 天给窗口。
- **价值度量**：非计划停线次数、停线时长、节拍达成率。

### 场景 2（P0）核心设备综合成本最优：让"现在修"和"再等等"可算

- **问题**：注塑机液压、烤漆风机、冲压机等大型设备，修不修、何时修是经营决策。
- **方案**：完整决策会诊 + 方案卡，含排产冲突、备件到货、人力、经济性。
- **价值度量**：非计划停机时长下降、备件呆滞率下降、MTTR 下降。

### 场景 3（P1）供应商质量联动：从"管自己的设备"到"管供应链"

- **问题**：供应商来料质量波动，通常要等到整车下线检测才发现，追溯成本极高。
- **方案**：供应商设备状态 + 关键工艺数据上报，集团侧做"来料质量 vs 供应商设备健康"关联分析；供应商健康看板驱动其自己做维护。
- **价值度量**：来料不良率、质量追溯时间、供应商整改闭环率。

### 场景 4（P1）集团对标：20 个基地用一套尺子

- **问题**：同型号注塑机在不同基地，MTBF 差 3 倍，没人说得清是设备问题还是维护问题。
- **方案**：统一命名空间 + 统一判据 + 统一 HI 口径 → 集团级对标看板。
- **价值度量**：基地间指标差异收敛度、最佳实践复制数量。

> **场景 4 是集团客户买单的核心动力**，也是对单体 PdM 产品的降维打击点。它要求"同型号设备的判据一致"，这就是为什么 docs/04 里反复强调判据库必须集中受控。

## 5. 部署拓扑：联邦而非集中

```
┌──────────────────────────────────────────────────────────────┐
│ 集团中心集群（10.167.2.175/176，K8s 1.28.2，Rancher 管理）      │
│  · 集团看板 / 跨基地对标（TiDB + TiFlash 读模型）               │
│  · 判据库 / 故障模式库 / 技能库（受控资产，全集团唯一）           │
```

### 5.1 三条铁律

1. **判据只在集团，数据只在基地。** 判据库是全集团唯一真相源（保证对标可比性）；原始数据不出基地。
2. **上行是"受控摘要"，不是"原始流"。** 上行的只有特征值、事件、诊断结论、方案卡。
3. **边缘永远能独立闭环。** 中心不可用时，采集→诊断→告警→本地报告仍可用，只是没有跨基地对标。

### 5.2 供应商域（轻量接入）

```
供应商侧（最轻，尽量零部署）：
  选项 A：供应商已有网关 → 通过受控 API 上报（推荐）
  选项 B：被授予只读看板 → 集团侧 SaaS 化视图
  选项 C：下发边缘小包 → 仅对 Tier1 且数据量大的供应商

禁止：供应商直连集团集群内网。
```

### 5.3 数据主权与跨境分级

| 数据级别 | 定义 | 境内基地 | 海外基地 |
|---|---|---|---|
| L1 原始波形 / 原始报文 | 含工艺细节 | 留基地 | **强制留基地（本地）** |
| L2 设备台账 / 故障记录 | 敏感 | 可上行 | 留基地，仅汇总上行 |
| L3 诊断结论 / 特征值 | 内部 | 可上行 | 脱敏后可上行 |
| L4 统计指标 / 对标 | 可共享 | 可上行 | 可上行 |

**海外特别要求**（需法务确认当地法规，如 GDPR、越南 PDPD 等）：本地处理、最短留存、可删除、可导出。设计上通过"本地自治 + 脱敏上行"满足。

## 7. 雅迪 case 的验收补充

| 补充项 | 判定标准 |
|---|---|
| 跨基地一致性 | 同一型号设备在 2 个基地的 HI 口径一致（差异仅来自真实劣化） |
| 供应商接入 | 1 家 Tier1 供应商完成受控上报，数据隔离正确 |
| 断网自治 | 模拟海外基地断网 7 天，本地业务不中断，恢复后补传完整 |
| 判据发布 | 集团发布新判据，20 个基地 24 小时内全部生效 |
| 行业包切换 | 切换行业包后，数据模型/判据/模板成套切换，无残留 |
| 组织权限 | 供应商账号越权访问集团数据的测试 100% 失败 |

## 8. 经济模型修正（对 docs/01 的补充）

单厂模型不适用于集团客户，需改为"三级摊薄"：

| 层级 | 一次投入 | 边际成本/基地 | 说明 |
|---|---|---|---|
| 平台与判据库（集团） | 高（¥180 万） | 0 | 集团一次性，全集团共享 |
| 单基地接入 | — | 中（¥25 万） | 边缘 + 采集 + 培训 |
| 单设备监测点 | — | 低（¥0.15 万/点） | 传感器 + 改造 |

**集团级 ROI 结论**：20 基地全部接入时，总投入约 ¥180 + 20×25 = ¥680 万；年化收益按单基地 ¥185 万 × 20 × 0.8（折损）= ¥2,960 万。**回收期约 3.4 个月**，明显优于单厂模型。

> 这也解释了雅迪为什么值得做：**平台的一次性投入被 20 个基地摊薄，这是集团客户的核心商业逻辑**。做单体项目的公司理解不了这一点，也就拿不到集团单。
