## 1. 总体策略：五个阶段 + 五道门

```
Ph0 规格       Ph1 数据底座     Ph2 诊断大脑     Ph3 交互决策     Ph4 边缘推广
2 周            4 周            5 周            4 周            3 周
  │               │               │               │               │
 G0              G1              G2              G3              G4
方案评审        数据就绪        模型达标        决策闭环        上线验收
```

**核心纪律：每道门不通过，不许进下一阶段。** 宁可延期，不可带病推进——工业项目的返工成本是软件项目的 5–10 倍（因为要等停机窗口）。

## 2. 阶段详解

### Ph0 · 规格与立项（2 周）

| 项 | 内容 |
|---|---|
| 目标 | 冻结需求与架构基线，取得立项批准 |
| 关键活动 | 本套文档评审；D1–D10 决策拍板；现场调研（3 台候选设备）；数据可得性摸底 |
| 交付物 | 本套文档 v1.0；D1–D10 决策记录；现场调研报告；预算批准 |
| **G0 门** | 设备副总签字 + 架构委员会评审通过 + 预算到位 |

**G0 检查项：**
- [ ] 范围边界（做什么/不做什么）已书面确认
- [ ] 首期设备清单已确定（≤ 20 台，含关键度分级）
- [ ] 数据可得性已核实（有无测点、有无历史故障记录）
- [ ] 专家投入承诺书已签
- [ ] 合规路径（等保定级）已明确

---

### Ph1 · 数据底座（4 周）

| 项 | 内容 |
|---|---|
| 目标 | 让设备"说上话"，数据可信可用 |
| 关键活动 | 协议接入（3 类）；统一命名空间建模；时序库部署；数据质量门；校准核查 |
| 交付物 | 可运行的采集链路；设备台账；数据质量报告；接入 SOP |
| **G1 门** | 数据就绪 |

**G1 检查项（硬性）：**
- [ ] 3 台设备、≥ 20 个测点稳定采集 ≥ 14 天
- [ ] 数据完整率 ≥ 99%
- [ ] 时间戳偏差 ≤ 50 ms（全链路）
- [ ] 100% 测点有校准记录且在有效期
- [ ] 数据质量分 ≥ 85（7 日均值）
- [ ] 断流/超量程能被正确识别

> **G1 是全场最容易被"糊弄过去"的门。** 很多项目在这里妥协，然后在 Ph2 花 3 倍时间还债。**这一关必须硬。**

**风险与对策：**

| 风险 | 对策 |
|---|---|
| 老设备无数字接口 | 加装振动传感器（独立采集，不依赖 PLC） |
| 协议文档缺失 | 抓包分析 + 厂商支持 |
| 无历史故障记录 | 用合成数据 + 迁移学习，同时启动"从现在开始记录" |

---

### Ph2 · 诊断大脑（5 周）

| 项 | 内容 |
|---|---|
| 目标 | 让模型"看懂"数据，输出可信的 HI 与故障假设 |
| 关键活动 | 特征工程；判据库建设（Top 8 故障模式）；SD/HA/PA 实现；黄金数据集标注；模型评测 |
| 交付物 | 诊断引擎；故障模式库 v1；评测报告；特征字典 |
| **G2 门** | 模型达标 |

**G2 检查项：**
- [ ] 黄金数据集 ≥ 30 例（含拆检报告）
- [ ] 关键故障模式召回率 ≥ 85%（首期可放宽，Ph5 提到 90%）
- [ ] 回放集误报率 ≤ 1.0 次/台·周
- [ ] 每条 HI 都有贡献度分解
- [ ] 降级模式正确率 ≥ 95%
- [ ] 失效案例报告已完成（≥ 5 例）

> **注意：首期召回率目标 85% 而非 90%。** 因为样本少，硬凑 90% 一定是过拟合。宁可诚实报 85%，在运营期用真实数据提升。

**并行工作：** 故障模式库需要设备专家每周 4 小时，**从 Ph0 就要开始**，不能等 Ph2 才找人。

---

### Ph3 · 交互与决策（4 周）

| 项 | 内容 |
|---|---|
| 目标 | 让"会打字的人"能诊断，让诊断能变成方案 |
| 关键活动 | MCP 服务；Harness 运行时；四角色会诊 + Evaluator；方案卡；EAM 集成；告警路由 |
| 交付物 | 可对话的诊断入口；方案卡；告警体系；审计链 |
| **G3 门** | 决策闭环 |

**G3 检查项：**
- [ ] 100 条真实问题的意图识别 ≥ 95%
- [ ] 每条结论 100% 有证据引用
- [ ] 提示注入红队 20 例 100% 拦截
- [ ] 方案卡 100% 含经济性计算
- [ ] 备件未到货时不会推荐早于到货日的窗口（关键场景）
- [ ] 工单草稿创建成功率 ≥ 99%（含重试）
- [ ] Stop Hook 能拦截"假完成"（注入超时场景验证）

---

### Ph4 · 边缘与推广（3 周）

| 项 | 内容 |
|---|---|
| 目标 | 数据不出厂也能跑；从 3 台扩到 20 台 |

- [ ] 运维手册 + 值班表就位
- [ ] 培训完成（3 类角色）
- [ ] 验收清单 42 项全通过

## 7. 关键路径与浮动

```
硬件采购(3w) ──► 安装(1w) ──► 数据积累(2w) ──► G1
                                              │
判据库(从Ph0开始,持续) ────────────────────────┤
                                              ▼
                                       特征工程(2w) ──► 模型(2w) ──► G2
                                                                  │
EAM接口(2w) ──────────────────────────────────────────────────────┤
                                                                  ▼
                                                          Harness(2w) ──► 会诊(2w) ──► G3 ──► 边缘(3w) ──► G4
```

**关键路径：硬件采购 → 数据积累 → 特征/模型 → 决策 → 边缘。**

**最大风险：硬件采购周期（进口传感器可能 6–8 周）。** 对策：Ph0 就下单，或用国产替代先跑通。

## 8. 培训与能力建设（本土化落地关键）

### 8.1 三类角色，三套材料

| 角色 | 时长 | 内容 | 考核 |
|---|---|---|---|
| 一线运维 | 2 小时 | 怎么问、怎么看报告、怎么确认 | 现场操作 5 题 |
| 维修班长 | 3 小时 | 方案卡解读、窗口权衡、拒绝原因填写 | 案例判断 3 题 |
| 设备工程师 | 1 天 | 判据原理、频谱识读、误报分析、基线重置 | 案例分析 5 题 |

### 8.2 培训原则（本土化）

1. **不讲算法，讲场景。** "这个图说明轴承外圈有麻点" 比 "包络谱的 BPFO 谐波" 有用。
2. **不讲功能，讲动作。** "看到橙色，你要做这三件事"。
3. **必须有"反面案例"。** 讲一次误报是怎么发生的，比讲十次正确诊断更让人信任。
4. **培训后 2 周内必须实操**，否则忘光。
5. **老师傅做讲师**，不是厂商做讲师。

### 8.3 知识资产沉淀

| 资产 | 形式 | 维护 |
|---|---|---|
| 诊断案例库 | 结构化（现象/证据/结论/验证） | 每次闭环后追加 |
| 技能库 | Markdown（受控） | 季度评审 |
| 误报分析库 | 表格（原因分类/改进） | 每月 |
| 培训视频 | 5–8 分钟短视频 | 按需 |

## 9. 变更控制

| 变更类型 | 审批 | 影响评估 |
|---|---|---|
| 范围增加 | 设备副总 + 项目经理 | 工期/成本 |
| 判据调整 | 设备专家 + 架构师 | 误报率/召回率 |
| 模型替换 | 治理委员会 | 全量回归 |
| 架构变更 | 架构委员会 | ADR |
| 延期 > 1 周 | 设备副总 | 里程碑重排 |

**变更必须书面，口头变更一律不认。** 这不是官僚，是工业项目里唯一能保护团队的东西。

## 10. 退出策略（Exit Criteria）

项目在以下情况应主动止损或转向：

| 信号 | 判断 | 动作 |
|---|---|---|
| G1 三次未通过（数据始终不可信） | 基础条件不具备 | 暂停，先做数据治理专项 |
| Ph2 结束召回率 < 60% 且无改善路径 | 数据/判据不足 | 缩范围为"规则告警"，放弃 AI 诊断 |
| 方案卡采纳率 < 30% | 决策层不认 | 回到 Ph0 重做业务流程 |
| 关键干系人变更 | 政治风险 | 重新对齐目标 |

**敢于止损，也是工程能力的一部分。**
