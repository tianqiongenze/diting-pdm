### 3.9 Web 端交互实测（无头浏览器 · 2026-10-23）

用真实浏览器（Playwright + Chromium 156 无头）走完看板全部用户路径，
**46/46 通过**。这一层是 httpx 版 E2E 覆盖不到的：不执行 JS、不渲染 DOM，
就发现不了下面这类问题。

| 实测项 | 结果 |
|---|---|
| 看板渲染（6 个面板 + KPI 有实际数值 + 热点表 20 行） | ✅ |
| 输入位号 → 点「诊断」→ 结果含 HI/等级/维度分解/证据 | ✅ |
| 点「趋势」→ SVG 折线图渲染（70 点） | ✅ |
| 点「会诊」→ 方案卡生成（含 verdict/风险/状态） | ✅ |
| 无 JS 运行时异常、无资源 4xx/5xx | ✅ |

**本轮抓出 3 个此前未发现的缺陷**，均已修复：

1. 看板「诊断」主按钮绑定 `diagnose()` 而实际函数是 `diag()` → 点击报
   `ReferenceError`，功能完全不可用（热点表内的行按钮反而是对的，极易漏检）
2. 线上看板是旧版本：趋势图/诊断分解代码在仓库里，但 ConfigMap 从未更新
3. java-asset 详情接口查 `measure_point`（实际表名 `measurement_point`）→ 恒 500

> **新增验收项 3.9**：Web 端必须用真实浏览器验证，禁止仅以 API 200 判定交互可用。
> 详细记录见 [31_无头浏览器全端全链路测试报告](31_无头浏览器全端全链路测试报告.md)。

| 指标 | 观察值 | 目标 | 处置 |

| 告警响应率 | | ≥ 90% | 不足 → 检查路由与培训 |

**30 天是"证伪期"，不是"庆功期"。** 大部分 PdM 系统死在第 3 个月，因为没人看告警了。

## 11. 常见"假验收"陷阱（务必避免）

| 陷阱 | 表现 | 真相 |
|---|---|---|
| 用训练集验收 | 指标漂亮 | 过拟合，现场崩 |
| 只验收"能跑通" | 演示成功 | 没验异常路径 |
| 误报率用"天"算 | 0.1 次/天看着很低 | 换算成 3 次/台·周，不可接受 |
| 跳过降级测试 | 网络一直很好 | 现场第一次断网就崩 |
| 专家不签字 | 技术团队自评 | 判据可能是错的 |
| 验收即解散 | 上线后无人管 | 3 个月后废弃 |

> 最后一句话：**验收不是终点，是运营的起点。** 本清单的作用不是"通过"，是"知道自己在哪不踏实"。
