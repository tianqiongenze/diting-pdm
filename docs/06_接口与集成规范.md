## 1. 接口全景

| 类别 | 协议 | 方向 | 用途 | 鉴权 |
|---|---|---|---|---|
| 设备接入 | OPC UA / Modbus TCP / MQTT / S7 | 拉/订阅 | 采集 | 证书 / 白名单 |
| 边缘→中心 | MQTT + HTTPS | 上行 | 特征值、事件、结论 | mTLS |
| 服务间 | gRPC | 同步 | 内部调用 | mTLS + SPIFFE |
| 服务间 | Kafka | 异步 | 事件、回放 | SASL |
| Agent→工具 | MCP (JSON-RPC 2.0) | 同步 | 工具调用 | OAuth2 / mTLS |
| 前端→后端 | REST (OpenAPI 3.1) | 同步 | UI | OIDC |
| 平台→EAM | REST / SOAP | 双向 | 工单、备件、台账 | API Key + IP 白名单 |
| 平台→MES | REST / 数据库视图 | 只读 | 排产计划 | 只读账号 |
| 告警外发 | Webhook / 企业微信 / 短信 | 单向 | 通知 | 签名 |

## 2. 设备接入规范

### 2.1 统一测点路径

```
{site}.{area}.{asset}.{component}.{point}.{quantity}
SZ01.压缩车间.KA-101.驱动端轴承.DE_H.vibration.acc_rms
```

### 2.2 OPC UA 信息模型映射

| OPC UA 节点 | 本项目实体 |
|---|---|
| `Object`（Device） | Asset |
| `Object`（SubComponent） | Component |
| `Variable`（Sensor） | MeasurementPoint |
| `Variable.Value` | Series.value |
| `Variable.SourceTimestamp` | Series.ts（UTC ms） |
| `Property`（EngineeringUnits） | point.unit |

**要求：** 优先使用 OPC UA 的 `ServerCapabilities` + `NodeSet2.xml` 做自动发现，避免手工配点。

### 2.3 MQTT Topic 规范

```
上行：pdm/{site}/{area}/{asset_id}/telemetry       QoS1, 批量 100 点/包
      pdm/{site}/{area}/{asset_id}/waveform        QoS1, 二进制（protobuf）
      pdm/{site}/{area}/{asset_id}/event           QoS2, JSON
下行：pdm/{site}/{area}/{asset_id}/cmd/config      QoS1, 仅配置（非控制）
```

### 2.4 波形二进制格式（protobuf 示意）

```protobuf
message WaveformPacket {
  string mp_id       = 1;
  int64  ts_start_ms = 2;
  uint32 sample_rate = 3;
  uint32 channels    = 4;
  repeated float samples = 5 [packed = true];   // 交错存储
  string trigger     = 6;   // scheduled | threshold | manual
  uint32 quality     = 7;   // 0-100
  string unit        = 8;
}
```

## 3. MCP 工具规范（Agent 对外能力）

### 3.1 通用约定

- 协议：MCP over stdio（本地）/ Streamable HTTP（远程）
- 每个工具必须声明：`name`、`description`（含"何时不要用"）、`inputSchema`、`annotations`（`readOnlyHint`、`destructiveHint`）
- 所有返回统一信封：

```json
{
  "ok": true,
  "data": { },
  "meta": {
    "quality": 92,
    "degraded": false,
    "elapsed_ms": 320,
    "source": "tdengine:pdm_features",
    "trace_id": "01J..."
  },
  "evidence": [
    {"type": "series", "ref": "mp:KA-101.DE_H", "window": ["2026-10-01T00:00Z","2026-10-21T00:00Z"]}
  ]
}
```

**`evidence` 字段是强制的**：没有 evidence 的返回，上层不得生成结论（对应 FR-403）。

### 3.2 工具定义示例（3 个代表）

```json
{
  "name": "assess_health",
  "description": "计算设备在指定时间窗内的健康指数(HI)及其分解。当需要判断设备整体健康水平时使用。注意：若时间窗内数据质量分低于60，本工具会返回 degraded=true，此时不应给出确定性结论。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "asset_id": {"type": "string", "pattern": "^[A-Z0-9]{2}\\.\\S+\\.\\S+$"},
      "window": {
        "type": "object",
        "properties": {
          "start": {"type": "string", "format": "date-time"},
          "end":   {"type": "string", "format": "date-time"}
        },
        "required": ["start", "end"]
      },
      "regime": {"type": "string", "enum": ["auto", "rated", "partial", "startup"]}
    },
    "required": ["asset_id", "window"]
  },
  "annotations": {"readOnlyHint": true, "destructiveHint": false}
}
```

```json
{
  "name": "create_workorder_draft",
  "description": "在EAM系统中创建工单草稿（不派工、不占用备件）。仅在用户已确认维护方案卡后调用。调用前必须已获得人工确认令牌。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "recommendation_id": {"type": "string"},
      "confirm_token": {"type": "string", "description": "人工确认令牌，由审批流签发"},
      "window": {"type": "object"},
      "spare_parts": {"type": "array", "items": {"type": "object"}}
    },
    "required": ["recommendation_id", "confirm_token"]
  },
  "annotations": {"readOnlyHint": false, "destructiveHint": false, "requiresConfirmation": true}
}
```

```json
{
  "name": "query_series",
  "description": "查询测点时序数据（自动降采样到≤2000点）。不要用于查询超过90天的时间窗，应改用 assess_health 的趋势接口。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "mp_ids": {"type": "array", "items": {"type": "string"}, "maxItems": 10},
      "start": {"type": "string", "format": "date-time"},
      "end":   {"type": "string", "format": "date-time"},
      "agg":   {"type": "string", "enum": ["raw","1m","5m","1h","1d"], "default": "5m"}
    },
    "required": ["mp_ids", "start", "end"]
  },
  "annotations": {"readOnlyHint": true}
}
```

### 3.3 MCP 网关安全要求

| 要求 | 实现 |
|---|---|
| 工具级授权 | 按角色授予工具子集（操作工无 `create_workorder_draft`） |
| 调用配额 | 每用户 60 次/分钟 |
| 参数审计 | 全量记录（脱敏后） |
| 响应过滤 | 按数据行级权限过滤设备 |
| 版本协商 | 工具 schema 版本化，破坏性变更升 major |

## 4. 内部 REST API（节选）

### 4.1 资源

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/assets` | 设备列表（支持关键度、车间过滤） |
| GET | `/api/v1/assets/{id}/health` | 当前 HI + 趋势 |
| GET | `/api/v1/assets/{id}/diagnoses` | 诊断历史 |
| POST | `/api/v1/diagnoses` | 发起诊断（异步，返回 task_id） |
| GET | `/api/v1/diagnoses/{id}` | 诊断结果 |
| GET | `/api/v1/diagnoses/{id}/report` | HTML 报告 |
| GET | `/api/v1/recommendations` | 方案卡列表 |
| POST | `/api/v1/recommendations/{id}/confirm` | 人工确认 |
| POST | `/api/v1/recommendations/{id}/reject` | 拒绝（需原因码） |
| GET | `/api/v1/alerts` | 告警列表 |
| POST | `/api/v1/alerts/{id}/ack` | 已知悉 |
| GET | `/api/v1/audit/traces/{trace_id}` | 审计回放 |

### 4.2 错误码规范

| 码 | 含义 | HTTP |
|---|---|---|
| `PDM-1001` | 设备不存在 | 404 |
| `PDM-1002` | 数据质量不足 | 422 |
| `PDM-2001` | 证据缺失，拒绝生成结论 | 422 |
| `PDM-2002` | 置信度低于阈值，需人工 | 409 |
| `PDM-3001` | 权限不足（工具级） | 403 |
| `PDM-3002` | 需人工确认 | 428 |
| `PDM-4001` | EAM 接口不可用 | 502 |
| `PDM-5001` | 模型服务不可用（已降级） | 200 + `degraded=true` |

> **注意 `PDM-5001`：模型不可用不是错误，是降级。** 返回 200 + 标记，让上层继续走模板路径。

## 5. 事件规范（CloudEvents 1.0）

### 5.1 事件类型

## 6. EAM / CMMS 集成（防腐层设计）

### 6.1 集成矩阵

| 场景 | 方向 | 接口 | 频率 | 失败处理 |
|---|---|---|---|---|
| 设备台账同步 | EAM→PDM | REST 分页 | 每日 | 缓存上次快照 |
| 备件库存查询 | EAM→PDM | REST | 实时（缓存 15 min） | 返回"未知"而非 0 |
| 创建工单草稿 | PDM→EAM | REST POST | 事件驱动 | 重试 3 次 → 人工队列 |
| 工单状态回写 | EAM→PDM | Webhook | 实时 | 定时对账 |
| 维修记录回写 | EAM→PDM | 批量 | 每日 | 用于模型迭代 |

### 6.2 防腐层（Anti-Corruption Layer）

```
decision-service ──► EamAdapter（接口）──► MaximoAdapter / SAPAdapter / 用友Adapter
                          │
                          └─ 统一内部模型：WorkOrderDraft
```

**为什么必须防腐：** 不同厂用不同 EAM（Maximo / SAP PM / 用友 / 金蝶 / 自研），字段语义完全不同。**绝不能让 EAM 的字段名泄漏到诊断与决策逻辑里。**

### 6.3 工单草稿字段映射（示例）

| 内部字段 | Maximo | SAP PM | 说明 |
|---|---|---|---|
| `asset_code` | `ASSETNUM` | `EQUNR` | 设备编码 |
| `description` | `DESCRIPTION` | `KTEXT` | 描述 |
| `work_type` | `WOTYPE` | `AUART` | 工单类型 |
| `scheduled_start` | `SCHEDSTART` | `GSTRP` | 计划开始 |
| `labor_hours` | `ESTLABHRS` | `ARBEI` | 工时 |
| `materials[]` | `MATUSETRANS` | `RESB` | 备件 |

### 6.4 幂等与对账

- 所有写接口必须支持 `Idempotency-Key`（用 `recommendation_id`）。
- 每日 02:00 对账：PDM 侧"已创建"清单 vs EAM 侧实际工单，差异生成工单。
- **不允许"以为创建成功了"**——这是 Stop Hook 的数据基础。

## 7. 接口契约测试（Consumer-Driven Contract）

| 契约 | 提供方 | 消费方 | 工具 |
|---|---|---|---|
| MCP 工具 schema | mcp-server | agent-runtime | JSON Schema 校验 |
| REST API | 各服务 | 前端 | OpenAPI + Schemathesis |
| 事件 | 各服务 | 各消费方 | CloudEvents schema |
| EAM 适配 | EamAdapter | decision-service | Pact |

**规则：** 契约变更必须先在消费方加"兼容测试"，CI 中契约测试失败即阻断合并。

## 8. 版本策略

| 接口类型 | 版本方式 | 兼容规则 |
|---|---|---|
| REST | URL 路径 `/v1` | 新增字段兼容；删除/改义升版本 |
| MCP 工具 | schema 内 `version` | 破坏性变更升 major，双版本并行 ≥ 1 个迭代 |
| 事件 | `type` 后缀 `.v2` | 双发过渡期 ≥ 30 天 |
| 波形格式 | protobuf 字段号 | 只增不改不删 |

## 9. 限流与降级

| 接口 | 限流 | 降级策略 |
|---|---|---|
| 诊断 API | 10 并发/用户 | 排队 + 预计等待时间 |
| 波形查询 | 5 次/分钟 | 返回降采样版本 |
| LLM 调用 | 按预算 | 降级到小模型 → 模板 |
| EAM 写 | 20 次/分钟 | 异步队列 |

**降级顺序（必须严格遵守）：**
```
完整 LLM 会诊 → 单模型会诊 → 规则+模板方案卡 → 仅告警不带建议
```
任何一级都**不能**变成"系统不可用"。
