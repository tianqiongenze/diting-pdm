### 0.2 地址为什么这么长

`*.nip.io` 是公共 DNS 服务，会把域名里的 IP 直接解析回来
（`pdm-api.10.167.2.175.nip.io` → `10.167.2.175`）。
集群 Ingress 按域名分流，所以不能直接用 `http://10.167.2.175:32231/pdm-api/dashboard`
（会 404）。

### 0.3 打不开怎么办（按顺序试）

**① 确认能解析域名**

Windows：
```powershell
nslookup pdm-api.10.167.2.175.nip.io
```
应返回 `Address: 10.167.2.175`。

macOS / Linux：
```bash
ping -c 1 pdm-api.10.167.2.175.nip.io
```

**② 解析失败 → 手工加 hosts**（内网屏蔽公网 DNS 时常见）

Windows：用管理员打开记事本，编辑
`C:\Windows\System32\drivers\etc\hosts`，加一行：
```
10.167.2.175  pdm-api.10.167.2.175.nip.io
```
macOS / Linux：
```bash
sudo sh -c 'echo "10.167.2.175  pdm-api.10.167.2.175.nip.io" >> /etc/hosts'
```
保存后刷新 DNS（Windows：`ipconfig /flushdns`），再试。

**③ 还是打不开 → 先测端口通不通**

```bash
curl -o /dev/null -w "%{http_code}\n" http://10.167.2.175:32231/pdm-api/healthz
```
- 返回 `200`：网络通，问题在域名解析，回到 ②
- 返回 `000` 或超时：网络不通，找运维确认 32231 端口放行

| 检查点 | 预期 |
|---|---|

### 1.4 诊断工作台

1. 点左侧第四个图标
2. **进入即自动诊断** `FAN-00004`，无需手动点

**预期**：
- 左侧：健康指数 **0.0 红色**，SLA 4h，正常模式，rules-v0.2.0

## 2. API 抽查（可选，约 5 分钟）

适合开发/测试人员。以下命令在**能访问 10.167.2.175** 的机器上执行。

> 注意：所有 `/v1/*` 接口都要求 `X-Tenant-Id` 头，缺了会返回
> `400 missing X-Tenant-Id header`——这是**正确行为**，不是缺陷。

### 2.1 健康检查

```bash
curl -s -H "Host: pdm-api.10.167.2.175.nip.io" \
  http://10.167.2.175:32231/pdm-api/healthz
```
预期：`{"status":"ok","service":"python-diagnosis",...}`

### 2.2 诊断

```bash
curl -s -X POST \
  -H "Host: pdm-api.10.167.2.175.nip.io" \
  -H "X-Tenant-Id: site-a" -H "Content-Type: application/json" \
  -d '{"tenant_id":"site-a","asset_id":"FAN-00004"}' \
  http://10.167.2.175:32231/pdm-api/v1/diagnose
```
预期：含 `hi`、`level`、`contributions`、`evidence`、`trace_id`。

### 2.3 方案卡列表

```bash
curl -s -H "Host: pdm-api.10.167.2.175.nip.io" -H "X-Tenant-Id: site-a" \
  "http://10.167.2.175:32231/pdm-api/v1/cards?limit=5"
```
预期：`{"tenant_id":"site-a","count":N,"cards":[...]}`

### 2.4 资产服务

```bash
# 列表
curl -s -H "Host: pdm-api.10.167.2.175.nip.io" -H "X-Tenant-Id: site-a" \
  "http://10.167.2.175:32231/pdm-asset/api/v1/assets?limit=3"

# 详情（含测点）
curl -s -H "Host: pdm-api.10.167.2.175.nip.io" -H "X-Tenant-Id: site-a" \
  http://10.167.2.175:32231/pdm-asset/api/v1/assets/AGV-00006

# 关键度统计
curl -s -H "Host: pdm-api.10.167.2.175.nip.io" -H "X-Tenant-Id: site-a" \
  http://10.167.2.175:32231/pdm-asset/api/v1/assets/stats/criticality
```
预期：详情返回 `{"asset":{...},"measure_points":[...],"measure_point_count":6}`。

### 2.5 鉴权（负向验证）

```bash
# 无凭据 → 401
curl -o /dev/null -w "%{http_code}\n" \
  -H "Host: pdm-api.10.167.2.175.nip.io" \
  http://10.167.2.175:32231/pdm-api/dashboard

# 错误凭据 → 401
curl -o /dev/null -w "%{http_code}\n" -u a:b \
  -H "Host: pdm-api.10.167.2.175.nip.io" \
  http://10.167.2.175:32231/pdm-api/dashboard

# 正确凭据 → 200
curl -o /dev/null -w "%{http_code}\n" -u 'pdmadmin:3r5P-ygrg-WAcK-W0yB-Vz1q' \
  -H "Host: pdm-api.10.167.2.175.nip.io" \
  http://10.167.2.175:32231/pdm-api/dashboard
```
预期依次为 `401`、`401`、`200`。

## 4. 已知行为，不是缺陷

| 现象 | 解释 |
|---|---|
| `FAN-00004` 的 HI 恒为 0.0 | 该设备测试快照劣化严重，属预期 |
| 趋势图是水平直线 | 测试数据未模拟 HI 随时间劣化 |
| 同设备重复会诊卡号不变 | 30 分钟去重窗口，属预期设计 |
| 方案卡确认后不能再确认 | 终态保护，返回 409 |
| 请求缺 `X-Tenant-Id` 返回 400 | 多租户强制校验 |
| 看板需登录 | HTTP Basic Auth，fail-closed |
| 只有 1 个诊断服务副本 | 测试环境 CPU 配额不足，生产需 2 副本 |

## 5. 发现问题怎么记

每条缺陷请记录：

```
【编号】TEST-YYYYMMDD-NN
【严重度】阻断 / 严重 / 一般 / 轻微
【位置】看板 → 哪个面板/按钮；或 API 路径
【步骤】1. … 2. … 3. …
【预期】…
【实际】…
【附件】截图 / 浏览器控制台报错文本 / curl 返回体
```

**严重度参考**

| 级别 | 判定 |
|---|---|
| 阻断 | 页面打不开、按钮点了没反应、核心数据为空 |
| 严重 | 结果明显错误（HI/等级算错）、确认流程卡死 |
| 一般 | 显示错位、文案错误、个别字段缺失 |
| 轻微 | 样式细节、非关键提示语 |

## 7. 需要运维配合的事项

如果遇到以下情况，请转运维（不要自行改集群）：

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 32231 端口不通 | ingress-nginx 异常 | 查 `kubectl -n ingress-nginx get pods` |
| 看板 503 | 看板鉴权 Secret 缺失 | 查 `kubectl -n pdm-prod get secret pdm-dashboard-auth` |
| 所有 API 502/504 | 后端 Pod 未就绪 | 查 `kubectl -n pdm-prod get pods` |
| 页面功能与文档不符 | 看板 ConfigMap 未同步 | 跑 `bash impl/tools/deploy_dashboard.sh verify` |
