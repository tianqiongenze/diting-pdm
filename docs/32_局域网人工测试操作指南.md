### 0.3 地址为什么这么长

`*.nip.io` 是公共 DNS 服务，会把域名里的 IP 直接解析回来
（`pdm-api.10.167.2.175.nip.io` → `10.167.2.175`）。
集群 Ingress 按域名分流，所以不能直接用 `http://10.167.2.175:32231/pdm-api/console`
（K8s 不允许 Ingress 的 host 写 IP，会 404）。

### 0.4 打不开怎么办（按顺序试）

**① 确认能解析域名**

Windows：
```powershell
nslookup pdm-api.10.167.2.175.nip.io
```
应返回 `Address: 10.167.2.175`。

macOS / Linux：
```bash
ping -c 1 pdm-api.10.167.2.175.nip.io
```

**② 解析失败 → 手工加 hosts**（内网屏蔽公网 DNS 时常见）

Windows：用管理员打开记事本，编辑
`C:\Windows\System32\drivers\etc\hosts`，加一行：
```
10.167.2.175  pdm-api.10.167.2.175.nip.io
```
macOS / Linux：
```bash
sudo sh -c 'echo "10.167.2.175  pdm-api.10.167.2.175.nip.io" >> /etc/hosts'
```
保存后刷新 DNS（Windows：`ipconfig /flushdns`），再试。

**③ 还是打不开 → 先测端口通不通**

```bash
curl -o /dev/null -w "%{http_code}\n" \
  -H "Host: pdm-api.10.167.2.175.nip.io" \
  http://10.167.2.175:32231/pdm-api/healthz
```
- 返回 `200`：网络通，问题在域名解析，回到 ②
- 返回 `000` 或超时：网络不通，找运维确认 32231 端口放行

**④ 弹框输了密码还是 401**

口令可能在轮换。找运维核对 Secret：
```bash
kubectl -n pdm-prod get secret pdm-dashboard-auth -o jsonpath='{.data.password}' | base64 -d
```

## 7. API 抽查（可选，约 8 分钟）

适合开发 / 测试人员。以下命令在**能访问 10.167.2.175** 的机器上执行。

> 所有 `/v1/*` 接口都要求 `X-Tenant-Id` 头，缺了返回
> `400 missing X-Tenant-Id header`——这是**正确行为**，不是缺陷。
> 写操作还需 `X-Auth-Token`，未登录返回 `403`。

### 7.1 健康检查与总览

```bash
H='-H Host:pdm-api.10.167.2.175.nip.io'
B=http://10.167.2.175:32231/pdm-api

curl -s $H $B/healthz
curl -s $H -H "X-Tenant-Id: site-a" $B/v1/stats/overview
```
预期：`healthz` 返回 `{"status":"ok",...}`；
`overview` 返回 `total_assets=1200, assessed=1200, coverage_pct=100.0` 与四级分布。

### 7.2 登录与鉴权

```bash
# 登录取 token
TOK=$(curl -s -X POST $H -H "X-Tenant-Id: site-a" -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"Admin@2026"}' $B/v1/auth/login \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
echo "token 长度: ${#TOK}"

# 校验身份
curl -s $H -H "X-Auth-Token: $TOK" $B/v1/auth/me

# 错误密码 → 401
curl -s -o /dev/null -w "%{http_code}\n" -X POST $H -H "X-Tenant-Id: site-a" \
  -H "Content-Type: application/json" -d '{"username":"admin","password":"bad"}' $B/v1/auth/login

# 篡改 token → 401
curl -s -o /dev/null -w "%{http_code}\n" $H -H "X-Auth-Token: ${TOK%????}AAAA" $B/v1/auth/me
```

### 7.3 诊断（单点 / 批量）

```bash
# 单点
curl -s -X POST $H -H "X-Tenant-Id: site-a" -H "Content-Type: application/json" \
  -d '{"tenant_id":"site-a","asset_id":"FAN-00004"}' $B/v1/diagnose

# 批量（需登录，limit 控制台数）
curl -s -X POST $H -H "X-Tenant-Id: site-a" -H "X-Auth-Token: $TOK" \
  -H "Content-Type: application/json" -d '{"limit":20}' $B/v1/diagnose/batch
```
预期：单点含 `hi` / `level` / `contributions` / `evidence` / `trace_id`；
批量返回 `total` / `ok` / `failed` / `elapsed_ms`，`failed` 应为 0。

### 7.4 告警

```bash
curl -s $H -H "X-Tenant-Id: site-a" "$B/v1/alerts?limit=5"

# 同步（幂等：第二次 created 应为 0）

  -d '{"threshold_hi":70}' $B/v1/alerts/sync
```
预期：同步返回 `created` / `skipped` / **`superseded`** / `total_open`。
`superseded` 是本次被高级告警收敛的低级告警数。

## 9. 已知行为，不是缺陷

| 现象 | 解释 |
|---|---|
| 运营看板「在监设备」显示 1200，但列表只有 200 行 | 1200 是总量（取总览接口），200 是列表上限 |
| 保养计划 KPI 1200，列表只显示 300 条 | 同上，副标题已注明「当前展示 N 条」 |
| 同一设备不会同时挂红、橙两条告警 | 高级告警会自动收敛低级告警（`ack_by=auto-superseded`） |
| 告警「同步」第二次 `新建 0 条` | 幂等设计：同设备同规则未关闭时不重复建单 |
| `FAN-00004` 的 HI 恒为 0.0 | 该设备测试快照劣化严重，属预期 |
| RUL 显示「无劣化趋势」 | 测试数据 HI 不随时间下降，线性外推无斜率，如实返回空值 |
| 趋势图是水平直线 | 同上，测试数据未模拟劣化 |
| 同设备重复会诊卡号不变 | 30 分钟去重窗口，属预期设计 |
| 方案卡确认后不能再确认 | 终态保护，返回 409 |
| 点检任务提交后不能再提交 | 返回 `task already done` |
| 点检提交后备件计划到期日变了 | 设计行为：以本次完成为起点重算下次到期 |
| 知识库「删除」不生效 | 只增不删，避免经验丢失 |
| 请求缺 `X-Tenant-Id` 返回 400 | 多租户强制校验 |
| 未登录点写操作按钮被拦 | 强制鉴权已开启（`PDM_AUTH_REQUIRED=1`） |
| 系统运维表规模带 `≈` | 大表用统计信息估算，避免 `COUNT(*)` 全表扫描 |
| 批量诊断跑的时候页面略慢 | 每 15 分钟一次全量诊断（1200 台，约 26 秒），属正常 |
| 页面需要先弹框输密码 | 第一层 HTTP Basic Auth，与业务登录是两回事 |
| 告警列表最多显示 200 条，但 KPI 数字更大 | KPI 取 SQL 聚合的全量值；列表只是窗口，已关闭的沉在最后 |
| 告警中心大量红色告警显示「超时 3.0h」 | 4h SLA 的告警已超过时限，属真实状态，需人工处置 |

## 12. 需要运维配合的事项

如果遇到以下情况，请转运维（**不要自行改集群**）：

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 32231 端口不通 | ingress-nginx 异常 | `kubectl -n ingress-nginx get pods` |
| 页面 503 | 看板鉴权 Secret 缺失 | `kubectl -n pdm-prod get secret pdm-dashboard-auth` |
| 所有 API 502/504 | 后端 Pod 未就绪 | `kubectl -n pdm-prod get pods` |
| 页面功能与文档不符 | 看板 ConfigMap 未同步 | `bash impl/tools/deploy_dashboard.sh verify` |
| 告警数量长时间不更新 | 告警同步 CronJob 异常 | `kubectl -n pdm-prod get jobs`（应每 10 分钟一条） |
| 设备健康度大面积为空 | 批量诊断 CronJob 异常 | `kubectl -n pdm-prod get cronjob batch-diagnose` |
| 写操作全部 403 | `PDM_AUTH_SECRET` 未注入或已轮换 | 查 deploy 的 env 与 Secret |
| 页面整体变慢 | 批量诊断正在跑（每 15 分钟约 26 秒） | 属正常，稍等即可 |
